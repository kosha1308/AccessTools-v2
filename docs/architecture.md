# Архитектура AccessTools 2 — проект v0.14

## Главный принцип
Создаём **конструктор сначала**. Архитектура едина для NETWORK_ACCESS и остальных шаблонов. Конструктор и Runtime используют одну и ту же схему данных правил, а не разные «макеты» и «реальные» VBA-условия.

## Контур модулей
```text
ADMIN UI
  ├─ Каталог шаблонов → распознавание образца → поля/таблицы
  ├─ Редактор правил → AST условий → действия/сообщения
  ├─ Каталог источников/операций → параметры и зависимости
  └─ Валидатор → Sandbox test/Explain → Версии → Publish
                                                │
                                      Immutable Published Package
                                                │
RUNTIME UI (FIRST_LINE / COORDINATOR)            │
  → Template Registry → Field Resolver → Rule Compiler/Validator
  → Source Resolver (lazy, role-aware) → Evaluator → RuleOutcome/Issue
  → Action Planner → Annotation Writer / Report Generator / Superset output
```

## Инварианты
- TemplateId, FieldId, ColumnId, SourceId, RuleId, OperationId и ActionId — стабильные логические ключи, отдельные от DisplayName и A1 координат.
- Проверки — редактируемые сериализованные определения; алгоритмы — чистые примитивы с типовыми сигнатурами; Excel writer ничего не знает о названии шаблона.
- Любая бизнес-проверка NETWORK_ACCESS выражается конфигурацией или композицией общих операций; «специальный контроллер шаблона» не допускается.
- Schema и Rule AST валидируются до публикации. Отсутствующие источники, поля и ошибки вычисления не трактуются как PASS.
- Одна опубликованная версия — детерминированный пакет; черновики изолированы. Откат должен быть доступен без программиста.
- Обобщённый механизм сообщений: инициаторские ошибки отдельно от согласований и техинструкций координатора.
- Конфликты нескольких подсветок и примечаний одного адреса решаются детерминированным общим механизмом.
- Запись в Excel только через Writer, который учитывает владельца пометки и защищает существующее оформление.
- Источники независимы от шаблона, индексируются один раз на сессию при совместимой схеме/версии; lazy load по фактическим зависимостям.
- При старте Excel нельзя открывать сторонние книги «для проверки наличия шаблонов».

## Контракты, которые нужно утвердить до реализации
1. Формат Template/Field/Table/Rule/Source/Action/PublishedPackage и схема миграций.
2. Система типов и состояния EMPTY/MISSING/INVALID/UNAVAILABLE; пределы вычислений.
3. Сигнатуры операций и версионирование библиотек.
4. Правила вычисления scopes: Document/Field/Row/Table/Group; индексирование динамических строк.
5. Result/Issue/Action и маршрутизация по ролям.
6. Идемпотентная разметка, восстановление чужих примечаний, политики конфликтов.
7. Sandboxed preview в копии книги, объяснение вычислений, валидатор перед publish.
8. Версии пакетов, экспорт/импорт, локальные источники, безопасное восстановление при ошибках.

## Архитектурные проверки
Два контрастных шаблона — простой независимый и NETWORK_ACCESS — должны иметь выразимое описание в схеме до разработки сложных UI. Рабочее доказательство независимости — создание нового шаблона через Admin, не добавляя специализированного VBA.
