# PR-08: несколько правил и общие поля

База: `c4f45ad`, отдельная ветка `feat/pr-08-multiple-rules`, первоначальная база PR — `feat/pr-07-admin-vertical-slice`. PR39 не изменяется.

## Контракт

`CAtTemplateEditor` хранит независимые коллекции полей и правил. Переименование и перенос сохраняют FieldId/RuleId. Копия правила получает новые идентификаторы правила, выражения и действия, продолжая ссылаться на исходное поле. Удаление правила не удаляет поле. До 32 полей и 32 правил; существующие бюджеты AST/Writer продолжают действовать.

Редактор предлагает только три работающих условия: точное сравнение Text с учётом регистра через `OP_TEXT_EQUAL@1.0.0`, его отрицание узлом Not и обязательность через `OP_TEXT_REQUIRED@1.0.0`. Условия нынешнего редактора используют одно поле; базовая AST-модель по-прежнему допускает несколько FieldRef в выражении. Никаких обработчиков имён шаблонов нет.

Обязательность — чистая операция Text→Bool без параметров. OK с непустым после VBA Trim текстом даёт true; EMPTY и OK с пустым/ASCII-пробельным текстом дают false. Табуляция и неразрывный пробел не удаляются. Только эта точная версия операции может поглотить обязательства EMPTY класса Input и связанные E_EMPTY. Прочие состояния и технические обязательства сохраняются. StateIs не получает новых полномочий. Для равенства/неравенства EMPTY остаётся незавершённым вычислением.

Полный запуск получает один immutable context Resolver, вычисляет все активные правила и формирует структурированные `CAtRuleFinding`. FAIL каждого правила сохраняет собственное сообщение. Все ActionIntent передаются одному Planner/Writer, группирующему канонические MergeArea, включая разные FieldId с одним адресом. ERROR имеет приоритет над WARNING и INFO. При равном приоритете действует существующий порядок Writer, а сообщения сохраняют порядок правил.

Любой CANNOT_EVALUATE блокирует весь набор записи и очистки: прежние отметки остаются, причина видна в результатах. Полный завершённый запуск согласует весь набор: частичное исправление сохраняет актуальные замечания, полный PASS снимает только подтверждённые собственные отметки. Выключение/удаление правила исключает его действие при следующем полном запуске. При отсутствии активных правил интерфейс явно сообщает «Нет активных правил»; пустой завершённый набор позволяет очистить собственные отметки. Это не утверждение проверки бизнес-условий. «Только выбранное» всегда выполняет предпросмотр, включая выбранное выключенное правило, без изменения любых отметок.

Writer не изменён: пользовательские значения/формулы не восстанавливаются, вмешательство в оформление вызывает CONFLICT, .xlsx поддерживает только заливку. Запрос Notes в неподдержанном профиле отклоняет действие целиком, без скрытого понижения. Для .xls сохраняется прежний проверенный профиль; общий Note ограничен 512 символами, цели/действия — прежними бюджетами. Журнал локальный, только в текущей сессии; после потери сессии автоматического присвоения владения/восстановления нет. Книги автоматически не сохраняются.

## XML и совместимость

SchemaVersion `4.0.0` добавляет обязательный `Rule.Enabled` со значениями `true`/`false`. AST и свойства действий сохраняют прежний смысл. Схемы 1/2/3 читаются прежними низкоуровневыми API без переинтерпретации. Старые читатели должны отклонять схему4.

Визуальный редактор принимает свой точный профиль схемы4; компиляция обратно и сравнение XML защищают от потери неподдержанных настроек. Загрузка атомарна. Поддерживается явный импорт прежнего одноусловного черновика схемы3: FieldId/RuleId сохраняются, внутренние Locator/Expression/Action ID нормализуются, дальнейшее сохранение создаёт новый файл схемы4. Исходник не перезаписывается. Иные профили/версии отклоняются с диагностикой; универсальное хранение AST не ограничивается этим редактором.

## Проверка и демонстрация

Полный запуск `tests/Run-Tests.ps1` сохраняет 682 регрессии и добавляет `AtMultiTests`. Реальный Excel x64 проверяет модель/XML, обязательность и сохранение технических ошибок, команды настоящих UserForm через API, два FAIL в одной ячейке, частичное/полное исправление, перенос, разные FieldId с одной целью, .xlsx и поддержанный .xls, Notes, формулы и конфликты. Это программное управление настоящим Excel, а не подтверждение всех ручных действий мышью.

Финальная проверка: Excel 16.0 build17932, Office x64 — **746 PASS, 0 FAIL** (682 прежних +64 PR08). Доказательства: `artifacts/run-3459082afe53496792fc511cdd6e8c85`. Отдельно сохранённая демонстрационная книга — **14 PASS, 0 FAIL**; SHA256 `40B6395A435542F9C7229A385018B5BB341E6CB7D9185B8F4DC3296EA660A11A`. Встроенный пример открывался в настоящем modeless-окне: список трёх правил, общие поля, три условия и новые команды присутствуют. Полный ручной сценарий мышью не пройден.

`tools/Build-MultiDemo.ps1 -OutputDirectory <существующая папка>` создаёт автономный `AccessTools-Constructor-PR08.xlsm` со встроенными формами, кодом и примером, `PR08-synthetic.xlsx` и `PR08-example.xml`. Репозиторий не нужен для использования. `Test-AdminDemo.ps1` проверяет сохранённую структуру и привязку запуска (14 проверок).

Ручной сценарий:

1. Открыть демонстрационную .xlsm обычным разрешённым в организации способом. В том же Excel открыть синтетическую .xlsx. Нажать «Открыть пример», явно выбрать .xlsx.
2. При B2=`bad`, C2=`Laptop` нажать «Протестировать»: два FAIL, один PASS, B2 красная. В результатах — отдельные строки и оба сообщения.
3. B2=`other`: остаётся WARNING и жёлтая заливка. B2=`good`: все PASS, восстановлена исходная заливка, E2 остаётся формулой.
4. Сделать лист второго поля отсутствующим в настройке: CANNOT_EVALUATE, прежние отметки не снимаются по предположению. Вернуть Input.
5. Перенести общее поле в D4 через выбор в Excel, поместить туда `bad`: обе ссылки сохраняются, прежняя цель безопасно согласуется.
6. Сохранить конфигурацию новым именем, закрыть и загрузить: все поля/правила и настройки восстановлены.
7. Убедиться, что у двух правил разная серьёзность; затем добавить другое поле с тем же адресом и правило для него: одна физическая отметка, все сообщения сохранены.
8. Копировать/переименовать/выключить/удалить правило, отфильтровать по полю. «Только выбранное» не меняет отметки остальных. Для .xlsx запрос Note должен явно отказать.

Номинальное окно уменьшено с 1020×720 до 900×650, есть компактная раскладка и вертикальная прокрутка. Ручная приёмка при Windows 125%/200%, колесо мыши, Office x86 остаются непроверенными; геометрические API-тесты не заменяют DPI-проверку. Сохраняются два прежних UNVERIFIED сценария Writer. Причина пользовательского сообщения r5 «не раскрасилась ячейка» неизвестна: результат правила/Writer не сохранился; PR08 не объявляет этот инцидент диагностированным.
