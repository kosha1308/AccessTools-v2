# Вычисление «Правила и исключения»

Продолжение PR17; тринадцать готовых проверок не изменены. Добавлен отдельный
вычислитель RULES для будущих проверок заявки и результатов Superset.
Он ещё не подключён к общему runner и не делает выпуск 2.0 готовым.

## Контракт

- `ATNetworkRulebookCompiler.Compile(raw, protocols)` возвращает
  `ATNetworkRulebookResult`: State/Policy/Diagnostics. RAW должен быть
  COLLECTION<ROW<RULES_RAW>>, protocols — снимок активного каталога.
- `Policy.Technical(source, destination, ports, protocol, budget)` проверяет
  условия технической строки. IP срабатывает по пересечению в заданной области;
  порт требует полного покрытия **одним** правилом. Это trigger общих правил,
  а не разрешение инициатора: его subset/deny-policy не менялась.
- `Policy.Superset(ip, hostname, service, budget)` вычисляет правила для
  фактической строки Superset. Existing service сравнивается целиком, без
  разбиения названия по пробелам. Результирующий service хранится отдельно.
- Hostname: exact > prefix > contains, затем длина; регистр и конечная точка
  незначимы. Приоритет считается среди подходящих IP/service-условий.
  Равные лучшие правила сохраняются вместе; правила без hostname независимы.
- Результат OK — неизменяемый COLLECTION<ROW<RULE_MATCH>> со всеми outputs:
  RULE_NAME, SERVICE_RESULT, DEST_GROUP, APPROVAL, COMMENT, SEVERITY, INSTRUCTION.
  Каждый output сохраняет ref исходного правила. Разные непустые service/group
  отмечаются CONFLICT, без случайного выбора. OK означает завершение вычисления,
  а не бизнес-допуск или отсутствие согласований.

Пустой ACTIVE означает неактивность согласно комментарию заголовка предоставленной
книги; активные строки без условий/результата, неизвестные enum, ошибки ячеек и
неверные IP/порты блокируют всю компиляцию. Пустая severity = INFO, как в legacy.
Instruction может быть самостоятельным результатом правила.

Проверены семантические контракты прежнего AccessTools на commit
`d9aa9b88f9193c0d2935d99c5cc8ecca3865687c`; реализация и тесты v2 самостоятельные.
В строгом опубликованном формате разделитель `|` не поддерживается для
условий и многозначных outputs service/group/approval.

## Ограничения контекстов

Service+port/protocol запрещены одной строкой схемы: эти данные происходят из
разных контекстов. Superset не придумывает технические порты; такие правила
предназначены Technical. Service-условия предназначены Superset. Подходящее
hostname-условие без доступного hostname требует ручной проверки.
Неизвестный протокол, неверный IP/порт/hostname также требуют ручной проверки,
без частичного результата. Системная ошибка/лимит — ERROR.

Лимиты: общий budget200000, до10000 строк, текст65536, output32767;
IP и порты не разворачиваются поэлементно. Исходные книги не изменяются.
Стандартные тесты используют вымышленные данные, приватные книги не нужны.
