# PR-07 r5 — визуальный конструктор

Продолжение PR #39 от `2de52ee`, без PR-08 и слияния. Автономная демонстрационная `.xlsm`, две native VBA UserForms, без дополнительных установок. Сохраняются Schema3 и смысл1/2, стабильные FieldId/RuleId, существующие Resolver/Evaluator/Writer и автоматические журналы r4.

## Текущие команды

- **Протестировать** — заново прочитать явно выбранную книгу, вычислить правило и вызвать безопасный Apply. FAIL наносит/обновляет отметки; PASS очищает прежние собственные отметки, в том числе после переноса поля. Незавершённый результат CANNOT_EVALUATE не очищает их. Результат правила и фактический результат Writer показываются раздельно. Автосохранения книги нет.
- **Предпросмотр без изменений** — только чтение/вычисление, без журнала и Writer.
- **Очистить отметки** — отдельная административная команда. Кнопка «Нанести отметки» удалена из основного интерфейса.
- **Выбрать из Excel** рядом с названием — независимый выбор в явно указанной книге, без обязательного выбора листа проверяемого поля. Считывается Value2 верхней левой ячейки одного объединения; пустое значение/Excel error/чужая книга/несколько областей отклоняются до замены названия. Отмена сохраняет прежний текст. Адрес поля не меняется, текст можно редактировать и сохранять в XML с тем же FieldId.

## Компоновка

При достаточной ширине — три колонки без горизонтальной прокрутки. Узкое окно переключается на последовательные секции: навигация, свойства, карточки. Высота карточек определяется фактическим текстом через WordWrap/AutoSize; длинные сообщение и ожидаемый текст не обрезаются. Подробности показываются в расширенном режиме. Размер содержимого вычисляется по границам видимых элементов; вертикальная полоса появляется только при переполнении. Zoom100 и шрифт10pt сохраняются, нижние команды переносятся по строкам и остаются вне прокрутки.

Сохранены русская палитра, выделение правила, лист сразу после загрузки XML, явный выбор книги, цветные результаты PASS/FAIL/CANNOT, раскрываемая диагностика и копирование замечания. Сборщик встраивает формы из `ui/forms.json`; кнопка листа и Alt+F8 вызывают общий AtAdminOpen.

**Колесо мыши не реализовано:** штатный MSForms ввод над вложенным полем форму не прокрутил. Небезопасный hook/subclass не подключён. Альтернатива — обычная вертикальная полоса и кнопки ↑/↓, доступные также через Tab/Enter. Обоснование и отдельный результат оконного исследования: [окна и колесо](pr39-r5-window-and-wheel.md). Реальный Windows DPI200 требует ручной проверки; размеры480×300pt не доказывают DPI200.

## Окна и безопасность

Воспроизведён один вариант «исчезновения»: при переключении между двумя книгами форма остаётся Visible=True, но оказывается за другим SDI-окном Excel. Добавлен ограниченный приёмник стандартных событий этой Application; он поднимает существующую форму без активации, смены владельца окна или HWND_TOPMOST. Handle определяется по временному уникальному заголовку, затем проверяется PID. Во время выбора Range обработка приостанавливается, при закрытии/выгрузке отключается. Новые экземпляры формы при повторном открытии не создаются, явный выбор книги и настройки сохраняются. Нативных обратных вызовов Windows, hook/subclass, таймеров и изменения Application flags нет.

Журналы остаются под `%LOCALAPPDATA%\AccessTools\Journals`, без выбора папки. Завершённые проверенные записи очищаются; конфликты/прерывания/чужие файлы сохраняются. Межсессионного восстановления нет. [Сравнение v1/v2 и обоснование](pr39-annotation-options.md) и [ограничения Writer](pr06-excel-writer.md) остаются в силе: `.xlsx` — только заливка; Note отклоняет действие целиком. Заливка+Note — только доказанный `.xls`/Excel16 build17932/Win64. Значения/формулы пользователя не восстанавливаются из старого снимка; stale plan и конфликты оформления блокируются.

## Короткая повторная проверка

1. Открыть r5, нажать кнопку листа, проверить Alt+F8. При блокировке макросов сохранить сообщение Office; защиту ради демонстрации не отключать.
2. На синтетической `.xlsx`: лист Input, A1=`Название`, B2=`no`, соседняя формула/пользовательское оформление. Выбрать книгу; кнопкой **Выбрать из Excel** взять название A1, затем отдельно задать проверяемый B2. Повторить с объединением и отменой Esc; проверить ручное редактирование названия.
3. Ожидаемый текст=`yes`, сообщение/цвет по выбору. **Предпросмотр без изменений** даёт FAIL без изменений. **Протестировать** даёт FAIL и заливку без выбора папки и автосохранения. Результат Writer виден отдельно.
4. Изменить цвет/сообщение, затем адрес на другую заполненную ячейку; тест должен обновить отметки и очистить старый адрес. Исправить значение/формулу на `yes`; тест PASS снимает собственные отметки, сохраняя новый ввод и исходное оформление.
5. Проверить EMPTY/MISSING/INVALID, чужой цвет после нанесения и явный отказ Note в `.xlsx`. На поддерживаемом `.xls` повторить с Note. Чужие данные/оформление не должны стираться.
6. Сохранить XML, закрыть/открыть редактор, загрузить XML: название/настройки/лист сохранены, книга выбирается явно. Поработать с несколькими книгами и листами, повторно открыть редактор: одна форма и прежнее состояние. Выбор Range не должен блокироваться оконным приёмником; после закрытия окно само не появляется.
7. При Windows125/150/200% проверить читаемость, переход к компактным секциям, отсутствие горизонтальной прокрутки и доступность нижних команд. Для вертикальной прокрутки использовать полосу или ↑/↓. Колесо остаётся известным ограничением, а не принятой возможностью.

Сборка: `tools/Build-AdminDemo.ps1 -OutputPath <новый абсолютный .xlsm>`; проверка: `tools/Test-AdminDemo.ps1 -Path <путь>`; полный набор: `tests/Run-Tests.ps1`. Нужен уже разрешённый VBA Project API; Trust Center скриптами не меняется. Полный конструктор, NETWORK_ACCESS, рабочая публикация, Ribbon и PR-08 не реализованы.
