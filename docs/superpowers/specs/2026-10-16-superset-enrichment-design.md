# Данные Superset для сводки: обновлённое ТЗ

Основание: docs/tz-update-2026-10-16.md. Полный первый выпуск по-прежнему требует
проверок заявки, Superset и сводки. Здесь реализуется отдельный проверяемый этап
сбора сведений из уже связанной и отфильтрованной вкладки, без записи в источник.
Строгий профиль/fingerprint остаётся следующим этапом чтения формы.

## Решение

ATSupersetEnricher.Read(ws,layout,lastDataRow,summaryIds) возвращает ATEvalResult:
COLLECTION<ROW<SUPERSET_SUMMARY>>. Layout задаётся снаружи существующим locator-ом;
не содержит template-specific headers в ядре. Обязательные FieldId:
SUMMARY_LINK, HOSTNAME, SERVICE, IS_NAME, SKUF_GROUP, SUPPORT_TEAM.
SUMMARY_LINK имеет usage DIRECT, остальные NONE: запись без связи не создаёт матч.
Новые source headers — «СКУФ ГРУППА ТП» и «КОМАНДА ПОДДЕРЖКИ»;
пробелы/регистр нормализуются имеющимся поиском заголовков.

Альтернативы: переносить старый монолитный writer сейчас рискованно; ограничиться
обновлением списка колонок недостаточно. Выбран независимый read-only адаптер
над текущим bounded Value2 reader. Результат потом использует общий writer.

## Связи и значения

summaryIds задаёт порядок строк результата. Допустимы положительные целые номера
1..2147483647 (Long/строковые цифры), ведущие нули канонизируются; дубли отклоняются.
В source SUMMARY_LINK номера разделяются запятой, точкой с запятой или CR/LF.
Повтор одного номера в одной физической строке не увеличивает счётчик; сравнение
точное, «1» не совпадает с «10». Корректные номера вне запрошенного набора игнорируются.
Повреждённые непустые ссылки дают ERROR без частичной сводки. Пустая связь пропускается.

Сначала проверяется видимость физической строки (AutoFilter/manual Hidden), затем
связь, затем значения относящейся строки. Скрытые и не относящиеся к запрошенным
номерам записи не влияют на значения и не создают ошибок своих полей.
Источник, фильтр, скрытие, формулы и оформление остаются без изменений.

ATSupersetTextSet дедуплицирует отдельные строки текста без учёта регистра,
срезая внешние обычные/NBSP пробелы, tab и zero-width/BOM; внутренний текст сохраняется. CRLF/CR -> LF.
Вывод — первый встреченный вариант каждого уникального значения, в порядке source.
SERVICE, IS_NAME, SKUF_GROUP и SUPPORT_TEAM выводят все значения через LF.
HOSTNAME выводится только при одном уникальном непустом значении; иначе EMPTY.
Это агрегация уже выбранных совпадений; IP/hostname refinement здесь не выполняется.

Каждый запрошенный номер остаётся в результате даже без совпадений. RowId = номер;
MATCH_COUNT — NUMBER числа уникальных физических относящихся строк; пять полей — TEXT.
При0 совпадений MATCH_COUNT=0, остальные EMPTY. Статус «не найден» и base поля/IP/
Rulebook-инструкции добавит coordinator pipeline; адаптер их не придумывает.
ERROR ячейки видимой относящейся записи останавливает этот результат контролируемо.
Результат immutable и не хранит COM-объекты, работает после закрытия источника.

## Ограничения и приёмка

Унаследованы10000 физических строк/1000000 ячеек. Запрошенных номеров<=10000,
шагов разбора ссылок/назначения совпадений<=200000. Не более10000 уникальных строк
в каждом наборе и32767 символов входного/итогового текста: превышение — явный ERROR, без усечения.
Отсутствующие semantic поля/неверный usage дают SUPERSET_SCHEMA; никакого кеша по имени.

Реальные временные листы: новые русские headers с лишними пробелами; несколько
номеров/значений, multiline/case duplicates, скрытые/отфильтрованные записи, hostname
однозначный/неоднозначный, номер без матчей, source cell error, malformed link и
границы, повторное чтение после ошибок/смены фильтра, source неизменён, снимок после
закрытия. Никаких старых исходников или реальных пользовательских данных в fixtures.
