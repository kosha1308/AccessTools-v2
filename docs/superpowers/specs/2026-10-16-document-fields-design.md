# Одиночные поля формы Excel

Продолжаем полный сценарий NETWORK_ACCESS + Superset + сводка координатора.
Следующий отдельный результат — чтение одиночных полей по внешнему описанию,
без изменения исходной книги. Полный production-профиль и fingerprint ещё не выпущены.

## Выбранный подход

Общий locator ищет ровно один полный текст якоря внутри ограниченного прямоугольника
по одному Value2-блоку. Поля инициатора/типа/срока не зашиваются в ядро. Прямые
координаты не подходят для переставленных полей, а эвристический поиск ближайшего
непустого значения мог бы взять другое поле. Поэтому используются только явные offsets.
Описание ATExcelFieldSpec immutable: FieldId, AnchorText, FirstRow/LastRow,
FirstColumn/LastColumn, RowOffset/ColumnOffset. Максимум1000000 ячеек поиска.

Offsets считаются от границы объединённого якоря: положительный RowOffset — от
его нижней строки, отрицательный — от верхней; положительный ColumnOffset — от
правой колонки, отрицательный — от левой. Нулевое смещение по оси сохраняет
верхнюю/левую координату. RIGHT=(0,1), LEFT=(0,-1), BELOW=(1,0), ABOVE=(-1,0).
Точные диагональные offsets также допустимы. (0,0) запрещено. Если целевая точка
попала в merge значения, читаем его верхний левый anchor. Выход за лист или за
область поиска для merge заголовка даёт явную ошибку. Значение может находиться
вне области поиска якоря. Никаких попыток самостоятельно угадать направление.

## Результат

ATExcelFieldValue — immutable снимок: FieldId, Found, SheetName, AnchorRef, CellRef,
Result As ATEvalResult. Геттер Result возвращает копию; в результате нет Range/Worksheet.
Found означает: однозначно найдены заголовок и ячейка значения, а не заполненность.
Нет якоря => Found=False, OK/TEXT/MISSING. Два якоря/неверная структура => Found=False,
ERROR с EXCEL_* кодом. Есть пустая ячейка/пустая формула/визуальные пробелы =>
Found=True, OK/TEXT/EMPTY. Ошибка Excel => Found=True, ERROR/EXCEL_CELL_ERROR.
Непустой исходный текст сохраняется целиком, числа — invariant TEXT. Даты/keywords,
EMAIL и другие бизнес-типы нормализуются следующим отдельным шагом по профилю.

ATEvaluationContext.AddField получает optional CellRef без нарушения существующих
вызовов. Snapshot и getters сохраняют адрес. Trace документного FIELD использует
именно этот адрес, включая ERROR и отсутствующие значения; не берёт адрес активной
строки таблицы. Значения/ошибки и правила короткого замыкания остаются прежними.

## Приёмка и границы

Реальные временные листы Excel: все4 направления с merged заголовком, точные offsets,
merged значение, границы листа, неполный/дублирующийся якорь, спецпробелы/формулы,
CVErr/нулевое число/многострочный текст, unchanged исходные данные и immutable snapshot
после закрытия книги. DSL читает найденное поле; trace содержит его реальный CellRef.
Повторный запуск после ошибки и ошибочный/неинициализированный spec безопасны.

Нет вызова macro по строке, внешних процессов в Runtime, изменения настроек Excel
или копирования закрытого старого кода/данных в публичный репозиторий.
Публикуемый профиль формы, fingerprint, rulebook, Superset и координатор остаются
обязательными следующими этапами. Технические решения делегированы пользователем.
