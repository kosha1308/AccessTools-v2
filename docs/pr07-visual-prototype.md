# PR-07 — русскоязычный визуальный прототип

Продолжение PR #39 от `3893ab9`, без PR-08. Последовательный мастер заменён двумя стандартными VBA UserForms. Дополнительных установок и внешних runtime-ресурсов нет: формы и элементы встроены в демонстрационную `.xlsm`. `ui/forms.json` нужен только при сборке; `.frm` содержат обработчики событий, общий импортёр создаёт native designer и встраивает его ресурсы средствами Excel.

## Пользователю

1. Откройте демонстрационную `.xlsm` в настольном Excel Windows и нажмите **«Открыть конструктор»**. Запуск зависит от вашей обычной политики макросов; системные настройки безопасности сборщик не меняет.
2. Откройте отдельную синтетическую книгу. Например: лист `Заявка`, ячейка `B2` со значением `нет`. В конструкторе обновите список книг и явно выберите эту книгу и лист.
3. Справа укажите название поля, нажмите **«Выбрать»** и выделите одну ячейку. Можно изменить адрес в поле формы. Условие — **«Текст равен»**, ожидаемое значение — например `да`.
4. Введите замечание для инициатора, уровень, цвет из палитры; явно выберите, требуется ли внутреннее примечание. Центральные карточки обновляются сразу. Переключатель простого/расширенного режима не меняет правило.
5. **«Сохранить»** создаёт новый файл конфигурации. Для новой редакции используйте новое имя: перезаписи нет. **«Загрузить»** открывает сохранённую конфигурацию для дальнейшего редактирования. Логические идентификаторы остаются прежними.
6. **«Протестировать»** только читает книгу. Окно результатов показывает итог, адрес, прочитанное значение, предполагаемые действия и внутреннюю диагностику. Замечание для передачи инициатору находится отдельно; кнопка копирует именно отображаемый текст без служебных данных.
7. **«Нанести отметки»** — отдельная запись: адаптер повторно читает книгу и вычисляет правило, затем вызывает существующий Writer. Для первой записи выбирается безопасная локальная папка нового журнала. Результат условия и состояние записи показываются раздельно.
8. Исправьте значение или формулу, снова протестируйте: PASS в предварительном тесте не снимает отметки. Нажмите **«Нанести отметки»** для их безопасной очистки либо **«Очистить отметки»** при явно выбранной связанной книге. Не закрывайте книгу конструктора до очистки: владение журналом ограничено живой сессией.

`.xlsx`: только заливка. При включённом примечании запись отклоняется целиком, без скрытого понижения возможностей. Заливка + Note доступна только в доказанном `.xls` / Excel 16.0 build 17932 Win64 профиле. Внутренние примечания предназначены 1ЛП/координатору; инициатор не использует надстройку. Почтовой отправки нет.

## Реализовано / недоступно

| Реализовано | Пока недоступно |
| --- | --- |
| Навигация по одному шаблону/правилу, карточки и свойства, русские подписи | Каталог множества шаблонов и правил |
| Поле Text, выбор книги/листа/ячейки, точное сравнение с учётом регистра | Новые типы операций, вложенный AST, исключения, таблицы |
| Сообщение, уровень, именованная палитра, явный Note | Произвольный редактор оформления Excel |
| Одна модель для двух режимов, сохранение/загрузка схемы 3.0.0 | Публикация, роли, adapters, NETWORK_ACCESS |
| Read-only тест, отдельные применение/очистка, окно результатов | Полная группировка замечаний, письма |

Сложные/неподдерживаемые конфигурации отклоняются целиком, а не переписываются под этот редактор. Цвет вне палитры из ранее сохранённого файла сохраняется как «Цвет из файла». UI не показывает AST, внутренние ID или числовые RGB.

## Архитектура и сборка

`CAtAdminEditor` управляет настройками, сохранением, загрузкой, preview/apply/clear. `CAtAdminPreview` содержит исходные typed результаты и представление для UI. Обработчики форм передают события в `modAtAdminUi`; Schema/Resolver/Evaluator/Writer не переписаны. Preview не создаёт журнал и не вызывает Writer; Apply никогда не использует сохранённый ActionPlan от предварительного теста. Новые визуальные конфигурации создают внутренние действия для FirstLine, а старые допустимые audience сохраняются при round-trip.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Build-AdminDemo.ps1 -OutputPath C:\SafeLocal\AccessTools.xlsm
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Test-AdminDemo.ps1 -Path C:\SafeLocal\AccessTools.xlsm
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Run-Tests.ps1
```

Папка должна существовать, файл назначения — отсутствовать. Для сборки требуется уже доступный Excel VBA Project API; скрипты не меняют Trust Center. Общий `Import-AtProject.ps1` собирает исходники и формы одинаково для demo и тестов. Привязка кнопки назначается **после SaveAs** по фактическому имени книги и повторно сохраняется. Сборка проверяет инициализацию обеих форм; отдельный тест повторно открывает только готовую demo read-only с отключёнными файловыми макросами и сверяет сохранённые формы/контролы/подписи/OnAction. Ручной импорт модулей не нужен.

## Проверка и ручная приёмка

Полный Excel x64 suite: **581 PASS, 0 FAIL** = 546 прежних +35 Visual. Отдельная проверка сохранённой demo: **12 PASS, 0 FAIL**. Visual suite проверяет адаптер, round-trip, стабильные ID, фактический ввод, отсутствие мутаций/Saved side effects при preview, отдельное применение и повторное вычисление, очистку после исправления, неполные значения, отказ Notes в `.xlsx`, палитру/карточки, оба режима, сохранение загруженного листа, выбор связанной книги при очистке, границы контролов и программный вызов публичного макроса открытия. Evidence: `artifacts/run-438a6c53bd5f4f2fa8858831f7afc51a` (host, source hashes, семь result-файлов, visual-assertions, worker exit 0).

**Это не ручная приёмка.** Пользователь должен отдельно проверить:

- Нажатие кнопки в открытой доставленной `.xlsm`, удобство навигации и читаемость русского текста.
- Windows 125% и 150%: отсутствие обрезания/наложений, доступность нижних кнопок. Есть адаптация размера/Zoom к доступному окну Excel; фактический DPI не менялся и не проверялся.
- Выбор ячейки мышью, отмену выбора/файла/папки, переключение между книгами и корректное сохранение загруженных настроек.
- Создание → сохранение → закрытие окна → загрузку → редактирование → новую редакцию.
- Read-only тест, копирование именно замечания в буфер/обычный текстовый редактор, отдельную запись и очистку после исправления в `.xlsx` и поддерживаемом `.xls`.
- Понятность отказов при чужой заливке/Note, изменении структуры, недоступном примечании и потере живой сессии.

Office x86, ручной clipboard/UI/DPI и crash recovery не подтверждены. Два прежних native API случая Writer остаются UNVERIFIED. Все ограничения владения, защиты, capabilities и восстановления [Writer](pr06-excel-writer.md) действуют. Книга автоматически не сохраняется Writer; запуск конструктора не означает публикацию готовой надстройки.
