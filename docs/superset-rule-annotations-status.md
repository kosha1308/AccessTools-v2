# Правила Superset и аннотации координатора

Продолжение PR22. Существующие Rulebook engine и пятнадцать проверок сохранены.
Новый `ATNetworkSupersetRules.Run(registry, rules, optionalBudget)` возвращает
immutable `ATNetworkSupersetResult`: State, Annotations, Report. Аннотации
SUPERSET_ANNOTATION имеют RowId номера сводки и SERVICE_RESULT/INSTRUCTION/STATUS.
Результат связан с точным исходным объектом registry: writer отклоняет аннотации
другого запуска даже при одинаковых адресах.

Для каждой пары IP/сеть заявки — найденная физическая строка вычисляется
пересечение адреса заявки с корректными IP-ячейками этой строки Superset.
Неверная исходная IP-ячейка пропускается целиком; корректная соседняя остаётся
доступной. Сети не разворачиваются. Это не даёт правилу одного IP сработать для
другого адреса, находящегося в той же запрошенной сети.

В прежний `Policy.Superset` передаются пересечение, фактический FQDN и исходный
сервис строки. Результат другого правила никогда не становится новым условием.
Приоритет exact/prefix/contains и равные лучшие правила, outputs и конфликт
определяет прежний engine. Разные сервисы разных исходных строк не объявляются
конфликтом; реальный конфликт выдаётся один раз на entry/source-контекст, при
этом все спорные результаты сохраняются. Подтверждённые результаты других строк
не исчезают из-за непроверенного hostname/сервиса или неполного источника.

В сервисе координатора сохраняется уникальный набор SERVICE_RESULT; инструкция
содержит название правила, сервис, группу, согласование, комментарий, инструкцию
и ref Rulebook. Повтор одного правила в одном entry не размножает блок текста.
Issue дополнительно указывает номер и фактическую строку Superset.
При отсутствии найденных строк контекст не придумывается: сервис пуст, инструкция
явно говорит, что правила не вычислены. Missing Rulebook также даёт явный SKIPPED.

`ATCoordinatorWorkbookWriter.Create(registry, optionalAnnotations)` сохраняет
прежний одноаргументный контракт. Bound annotations заполняют E/F сводки и меняют
баннер; исходные восемь Superset-колонок и пять enrichment-полей не изменяются.
При остановке правил базовая книга поиска остаётся доступной, E пуст,
F сообщает о незавершённой проверке. Перепутанный registry отклоняется до создания
новой книги. Формулы не исполняются, источники не меняются, сохранение явно внешнее.

## Шестнадцатая проверка и представление

`ATNetworkAccessChecks.ApplySupersetRules(previous15, annotations, catalog)`
добавляет NET.HOSTNAME_RULES. Пятнадцать прежних outcomes/decisions не переоформляются.
Ошибка, переполнение message template или нехватка1000 общего issue-capacity
блокируют только новый исход. Published keys для matches используют
`NET.HOSTNAME_RULES|severity|Имя хоста`, конфликт — `Конфликт Rulebook`.
Fallback — координатор/Superset, без ошибки ввода пользователя; Problems/Routing
могут переопределить представление. Incomplete сохраняется при изменении severity.

E/F книги содержат вычисленные outputs правил, а не каталоговые issue templates.
Настройки сообщений/маршрутизации применяются отдельно к отчёту через
ApplySupersetRules. Это разделение бизнес-результата и issue-представления; итоговый
пользовательский controller каналов ещё не подключён.

Лимиты: общий бюджет200000 на запуск,10000 annotations,990 issues,32767 символов
на блок/ячейку. Ошибка структуры/системы или бюджета отбрасывает все новые частичные
annotations и даёт BLOCKED. Готовые IP-совпадения и прежние проверки не стираются.
