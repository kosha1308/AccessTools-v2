# AccessTools 2 — архитектурный перезапуск

**Статус: PR-03 — типизированная структура AST, XML и статическая валидация; выполнения AST и пользовательской надстройки ещё нет.** AccessTools-v2 создаётся заново как универсальный конструктор Excel-шаблонов и проверок («constructor first»). Новый VBA в `src` не выполняет бизнес-проверки и не изменяет книги. Контракт и тесты: [PR-03 typed AST](docs/pr03-typed-ast.md); фундамент хранения — [ADR-008](docs/adr/008-schema-storage.md), [PR-02 validation](docs/pr02-validation.md).

## Порядок работы
- Сначала аудит и согласованная архитектура; затем универсальный конструктор шаблонов, полей и проверок; только после этого ручная конфигурация NETWORK_ACCESS.
- Все бизнес-правила, включая сложные, должны редактироваться через Admin без изменения VBA.
- Библиотека алгоритмов может быть написана в VBA, но все параметры, приоритеты, исключения, маршрутизация, имена, ячейки, комментарии и подсветки — в конфигурациях.
- Весь реальный Excel-результат (ошибки, подсветки, примечания, отчёты, Superset, сводка) должен быть сопоставим с AccessTools 1.
- **Новые функциональные модули не писать до согласования ТЗ и архитектуры с пользователем.**

## Распределение ролей
Владелец проекта передаёт конкретные задачи Codex вручную и выполняет ручное тестирование Excel, когда это необходимо. ChatGPT помогает с архитектурой, ТЗ и формулировкой заданий; Codex реализует утверждённые задачи и автоматизированные тесты. Задачи не запускаются автоматически.

Старые PR #1–31 закрыты как неактуальный цикл разработки. Их коммиты и исходные ветки сохранены для аудита.

## Утверждённая семантика IPv4
Дефисный диапазон IPv4 содержит **все адреса включительно** (например, `10.0.0.1-10.0.0.10` — 10 адресов). Проверка только границ запрещена. См. ADR-007 в `docs/decisions.md` и AC-16 в критериях.
