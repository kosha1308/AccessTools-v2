# Технические инструкции в сводке координатора

Продолжение PR23. `ATCoordinatorTechnicalNotes.Run(source, registry, policyReport,
optionalBudget)` переносит готовые NET.IP_EXCEPTIONS из `policyReport.SupersetIssues`.
Проверки и Rulebook engine не запускаются повторно и не изменялись. Используются
уже оформленные CoordinatorIssue: настройки сообщений/маршрутизации не применяются
второй раз. Отключённый Superset-канал исключает сообщение из переноса.

Immutable `ATCoordinatorNotesResult` содержит State, Rows (COORDINATOR_NOTES с
INSTRUCTION/STATUS по номеру сводки), GlobalCount, Incomplete, ErrorCode. Результат
связан с точным registry; registry теперь дополнительно сохраняет объект исходного
снимка заявки. Другой снимок отклоняется даже при одинаковых значениях. Прежние
вызовы и ручные результаты без provenance остаются совместимыми с прежними API,
но новый адаптер не принимает их для корреляции.

Сообщение привязывается по фактической ячейке к RAW технической строке, затем
попадает участникам связанности: прямым ссылкам на её концы и адресам, пересекающим
корректные целые IP-выражения источника/назначения. Так нижний IP внутри верхней
сети получает инструкцию; посторонний IP её не получает. Группы не раскрываются,
ошибочные IP-ячейки не разбираются частично. Контекст явно содержит всю связанность,
порт, протокол и обе исходные ячейки. Инструкция относится к связанности целиком.

Технический SERVICE_RESULT остаётся внутри подписанной инструкции; он не
приписывается каждому участвующему IP как собственный сервис. E и пять полей
Superset сохраняют прежнюю семантику. Непривязанные/общие сообщения не назначаются
произвольному адресу: GlobalCount виден в баннере, полный текст остаётся в
отдельном отчёте проверок. Неполнота готовой технической проверки также видна.

`ATCoordinatorWorkbookWriter.Create(registry, optionalSupersetAnnotations,
optionalTechnicalNotes)` дополняет F, сохраняя одно- и двухаргументные вызовы.
При ошибке нового адаптера книга остаётся с явной пометкой о неперенесённых
инструкциях. Если объединённый F длиннее32767 символов, старый текст сохраняется
целиком; число не поместившихся технических записей указывается в баннере.
Ошибка имеет приоритет над предупреждением при подсветке. Источники не меняются,
новые исходы проверок не создаются: их по-прежнему16.

Пределы: shared200000 шагов,10000 записей и32767 символов в поле. Ошибка бюджета,
структуры или BLOCKED техническая проверка дают error с пустыми Rows, без частичного
переноса. Соответствие переданного policyReport тому же запуску остаётся контрактом
вызывающей стороны; атомарный controller и source freshness предстоят.
