# PR-07 — первый редактор и сквозной запуск

**Статус: сквозной сценарий с безопасной очисткой после исправления входа; ручная приёмка UI остаётся открытой.** База `281d57d9badba6df8fa7da7e3d546d59cf85e355`, ветка `feat/pr-07-admin-vertical-slice`. PR-08 не начат.

Первоначальный пошаговый мастер заменён русскоязычными UserForms; актуальные запуск и ручная приёмка — [визуальный прототип](pr07-visual-prototype.md). Историческая первая вертикаль: открытая книга → лист → выбор ячейки → название поля Text → «равно тексту» → сообщение, серьёзность, RGB-цвет и явный выбор Note. Пользователь не редактирует AST/XML/VBA. Это один пошаговый редактор одного независимого скалярного правила; полного конструктора, распознавания шаблонов, публикации и ролей нет. Текущий интерфейс русскоязычный, цвет выбирается из палитры.

## Контракты и совместимость

`AtAdminDefinition` строит обычные Template/Locator/Field/Expression/Rule/Action, без процедур для определённого шаблона. Text equality — существующий `OP_TEXT_EQUAL@1.0.0`, `MODE=binary`, строгая регистрозависимая проверка. Другие AST этот небольшой редактор отклоняет целиком, не переписывая их под свой профиль.

Цепочка: явно выбранный Workbook → существующий `AtNewExcelResolver` → immutable `CAtEvalContext` → существующий Evaluator → `AtEvaluateRule` → `CAtRuleOutcome` → `AtOutcomeIntents` → существующие Planner/Writer. Ни Evaluator, ни Resolver не пишут в книгу.

`RuleOutcome` содержит RuleId, исходный EvalResult с диагностикой/requirements/provenance и статус. Только `IsComplete=True`, `ResultType=Bool`, канонические `true`/`false` дают PASS/FAIL. Всё остальное — CANNOT_EVALUATE; материализация действий для него запрещена. FAIL создаёт готовые ActionIntent по ссылкам Action → Field → A1 Locator. PASS создаёт пустой набор для сверки предыдущих собственных отметок. Это запуск одного правила и полного набора его отметок в отдельном журнале, не многоправильный scheduler; нельзя делить такой журнал между независимыми запусками других правил. Не реализованы зависимости исполнения правил и сложная маршрутизация результатов.

XML **SchemaVersion=3.0.0** использует прежний namespace и прежний AST 2.0.0. Только для Action добавлены обязательные `OnOutcome=FAIL`, `Message`, `FillColor` (каноническое целое 0–16777215), `AddNote=true|false`; требуется ровно один Field target. Прежние Trigger/Audience/Channel сохранены: Trigger Error/Warning/Info задаёт серьёзность, Audience — Initiator/FirstLine/Coordinator, Channel — Results для заливки либо Comment для заливки с Note. Approval/Report этим профилем не исполняются. Длина сообщения проверяется вместе с заголовком и уровнем Writer (512 символов всего).

Схемы 1.0.0 и 2.0.0 читаются и валидируются в прежнем смысле; новые свойства там запрещены. Схема 1 остаётся неисполняемой; AST схем 2/3 исполняется существующим Evaluator. Автоматического апгрейда нет. Старый loader откажет на 3.0.0. Существующий тест неизвестной схемы использует 99.0.0 вместо теперь поддерживаемой 3.0.0. Пример: [admin-equality.xml](../tests/fixtures/admin-equality.xml).

## Исправление по ревью PR #39: входы и владение отметкой

Историческая сверка собственной отметки использует отдельное `AtWOwnedEqual`: одинаковый полный набор ключей и все значения снимка, кроме точных `Data1..64`/`Formula1..64`. Поэтому допустимо исправить ввод до повторного запуска, но смена прямой заливки, Note/shape, MergeArea, листа/формата, отсутствие evidence или неподдерживаемая capability по-прежнему блокируют очистку/замену. Владение подтверждается только живым журналом, никогда цветом или текстом.

`Before` хранит исходное состояние оформления/структурные guards без значений и формул. `Observed`, `StepBefore`, `Expected`, `Actual` новой операции — полные свежие снимки. До первого изменения и при каждой мутации применяется прежнее полное `AtWEqual`; ввод, изменённый после составления плана, делает план устаревшим и блокирует запись. Recovery также сохраняет полную сверку и fail-closed поведение. Writer никогда не восстанавливает исторические Value2/формулы. Повторный FAIL обновляет свою отметку; PASS снимает её, в том числе по прежней координате поля. Перенос Note между областями по-прежнему требует очистки старой перед новым планом (capability PR-06).

Остальные ограничения PR-06 сохранены: Notes только `.xls` / Excel 16.0 build 17932 Win64; `.xlsx` — заливка без Notes; ограниченные стили/объединения; отказ на неподдерживаемых свойствах, protection, пользовательских Notes/threaded comments. Внешний журнал в новой выделенной локальной папке, владение только в живой сессии, никаких автоматических попыток recovery/rebinding после её потери. Полной транзакционности нет. См. [контракт Writer](pr06-excel-writer.md).
