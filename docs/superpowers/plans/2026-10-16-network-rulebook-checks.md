# Общие правила в проверке заявки

Base648ea41/PR18. Реализовать техническую NET.IP_EXCEPTIONS поверх готового
вычислителя, сохранив прежний Run с13 исходами. Новый RunWithRules добавляет14-й
исход и применяет presentation ровно один раз к каждому итоговому сообщению. Нижние hostname и сервисный контекст
обрабатываются будущим Superset matcher; завершение технической проверки не
считается завершением NET.HOSTNAME_RULES/полного потока.

1. ATNetworkRuleChecks.Run(source, compiledRules) читает только RAW технические
   строки, вызывает Technical с общим budget на заявку. Любая строка с ошибкой
   Excel/неизвестным контекстом получает понятное ручное предупреждение. Полностью
   пустая таблица — SKIPPED. Blank group/IP не создают PASS. Многозначный протокол
   разбирать тем же буквальным splitter, что уже использует проверка протоколов;
   все значения должны быть обработаны. Системный лимит обнуляет частичные hits
   только этого нового check, остальные13 остаются в новом композиционном runner.
2. Каждый hit становится сообщением с полным контекстом связанности, всеми outputs,
   инструкцией и исходной строкой Rulebook. Разные results конфликтуют явно, FAIL
   имеет приоритет над неполнотой. Требование согласования не считается ошибкой
   ввода пользователя. Каталог/маршрутизация могут переопределить presentation,
   ключ строится по исходной severity и применяется один раз.
3. Новый runner + переводы; тесты Excel-отчёта с фактической ссылкой на заявку,
   source unchanged. Стандартные тесты синтетические.
4. RED/GREEN полная регрессия, один свежий обзор, static7/7 gate9/9, чистая копия,
   документация и Draft PR поверх18. Без merge/release.

Review focus: не терять старые13 при ошибке нового check, однократный presentation,
не принимать частичный порт или часть протоколов, не терять инструкции/refs,
различать data/system errors, не дублировать сообщения для одинаковых протоколов.
Полный индекс Superset и координаторская книга остаются последующей задачей.

## Уточнение после обзора

Неполнота — отдельный immutable флаг ATCheckOutcome.Incomplete (defaultFalse
сохраняет старый контракт). Новая проверка сохраняет флаг даже при FAIL; после
severity override порядок ERROR -> FAIL, иначе incomplete -> SKIPPED.

Новый runner использует результат прежнего Run13 и отдельно оформляет только
новый check, затем объединяет immutable reports/decisions. Повторного применения
шаблонов к уже оформленным сообщениям нет. Ошибка expansion нового сообщения
заменяет только новый check на BLOCKED. Такой вариант предпочтительнее общего
atomic Apply14: он сохраняет готовые13 даже при ошибке настройки длинного
Rulebook-текста и не дублирует старую реализацию runner.
