# Пилот XLAM для координатора

Цель этого комплекта — первая локальная проверка сценария сетевых связанностей.
Это не официальный production-выпуск для коллег: синхронные FIRST_LINE и
COORDINATOR пакеты с опубликованной Admin-конфигурацией ещё не подготовлены.
Существующие 16 проверок сохранены.

## Состав

ZIP содержит папку AccessTools с AccessToolsv2.xlam, VERSION.txt, RELEASE_INFO.txt,
config/runtime.ini, manifest.json, русской инструкцией и искусственными
входными XLSX в папке «Пример». Пользовательские данные и реальные справочники
не включены. Надстройка без цифровой подписи. Автоматической установки нет.

Вкладка «AccessTools 2.0 — пилот» содержит «Проверить связанности» и
«Сохранить результаты», а также «Результаты проверки» и «Выбрать источники». Обработчики вызывают команды.
При открытии надстройки источники и индексы не загружаются: startup-кода нет.
Разметка [RibbonX](https://learn.microsoft.com/en-us/office/vba/Library-Reference/Concepts/customize-the-office-fluent-ribbon-by-using-an-open-xml-formats-file)
встраивается в Open XML пакет после сохранения XLAM и проверяется повторной загрузкой.

## Сборка и проверка

`tools/BuildPilot.ps1 -OutputDirectory <новая папка>` требует чистый Git commit,
запускает полный Excel regression, импортирует только src, компилирует и сохраняет
XLAM в отдельном Excel. Затем заново открывает сохранённый файл: первый SaveAs
может оставить Path исходного объекта пустым. Встраиваются версия, ReleaseId,
профиль и commit. Перед командами они сравниваются с установленными метаданными.
Смешанные версии блокируют UI. Источник DEV не выдаётся за готовый комплект.

Manifest содержит SHA256 всех файлов, кроме самого manifest. Его проверяет
`tools/TestPilot.ps1`. Runtime-проверка метаданных не является криптографической
защитой от намеренной подмены файлов. Источники пользователя выбираются отдельно,
не добавляются в manifest и не переписываются при проверке.

Сборка не перезаписывает существующую выходную папку. Перед созданием ZIP
выполняется загрузка из отдельной копии, проверка отсутствия тестовых модулей
и открытых источников на старте, несовпадения версии, полный сценарий на примере,
содержимое обеих книг и их сохранение. Затем интеграционный тест распаковывает ZIP
и повторяет проверку этой копии. Все Excel-процессы принадлежат конкретным тестам;
очистка сверяет PID и время старта. Настройки безопасности не меняются.

Тестовый пробник добавляется только в память ReadOnly-копии XLAM после проверки
состава модулей, не сохраняется и возвращает лишь путь. Так внутренний приватный
объект результата не передаётся через COM; см.
[VBA Error 98](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/a-property-or-method-call-cannot-include-a-reference-to-a-private-object-either).
Контрольные суммы файлов до и после совпадают.

В скрытом Excel пропускается только закрепление строк: попытка FreezePanes
останавливала создание сводки с ошибкой 1004. При видимом приложении сохранено
прежнее оформление. Расчёт, правила и данные результата этим не меняются.

## Граница приёмки

Программная загрузка XLAM из чистой копии не заменяет проверку регистрации
надстройки, видимости вкладки, кликов и отмен диалогов в обычном Excel.
Закрепление строк в видимом Excel также требует ручной проверки. Первое действие
пользователя — установка и запуск искусственного примера по вложенной инструкции.
Реальные заявки с рабочими данными ещё не прошли пользовательскую приёмку.
До её завершения комплект остаётся пилотом. Первая версия AccessTools.xlam может оставаться подключённой; вторая версия называется AccessToolsv2.xlam.

## Переименование 18.10.2026

По прямому решению пользователя имя второй надстройки изменено на AccessToolsv2.xlam, чтобы первая AccessTools.xlam могла оставаться подключённой. Это заменяет прежнее требование постоянного общего имени для данного пилота. Пути сборки, инъекции ленты, повторной загрузки и проверки обновлены; обращения к макросам уже используют фактическое имя книги. Новая сборка — 2.0.0-pilot.2. Правила и проверки заявки не менялись.

Проверка совместной загрузки использует искусственную пустую AccessTools.xlam; функциональность настоящей первой версии в этом тесте не проверяется. Предыдущий пилот v2 под старым именем следует отключить, рабочую первую версию отключать не требуется.
