# Архитектурные решения

## PR-07 — ограниченный Admin slice (ручная приёмка открыта)

По отдельному заданию владельца добавлены диалоговый редактор Text equality, явные свойства Action в схеме 3.0.0 и переход EvalResult → RuleOutcome → ActionIntent. [Контракт и ручной сценарий](pr07-admin-vertical-slice.md). 501 PASS в Excel x64, UI вручную не подтверждён. Полная приёмка блокируется существующим guard Writer: изменение значения помеченной ячейки даёт CONFLICT при очистке. Защита не ослаблена; требуется отдельное решение о контракте. PR-08 не начат; записи ниже исторические.

## PR-06 — ограниченный Writer и журнал владения

По заданию владельца реализованы ActionIntent/Plan/Receipt/OwnershipJournal, нормализация MergeArea, приоритеты, проверяемая запись/очистка и guarded recovery в живой сессии. [Контракт](pr06-excel-writer.md): внешний append-only журнал с lease и резервом восстановления; неизвестные состояния блокируют запись. 458 автоматических PASS в Excel x64 (394 прежних +64 Writer), два явно непроверенных native API случая. Notes ограничены доказанным профилем BIFF8/Excel x64 build 17932 и одной областью на лист; заливки поддерживают также несохранённые книги. Полный crash/power-loss recovery и Office x86 не подтверждены; ручная приёмка отдельно. PR-07 не начат.

## PR-05 — read-only Excel Resolver

По отдельному заданию владельца добавлено чтение явно переданной книги через существующие LocatorDefinition: A1, абсолютные DefinedName, LabelOffset и ограниченный scalar TableColumn; bounded table snapshots и immutable context. [Контракт и ограничения](pr05-excel-resolver.md): физические offsets столбцов передаются явно хостом, существующие XML-схемы не расширены; скалярные MergeArea читаются сверху слева, любые объединения в границах таблицы дают CONFLICT. В Excel x64 проверены 256 прежних +115 новых assertions; Office x86 и ручная приёмка не подтверждены. Writer/UI/внешние адаптеры/табличное исполнение не созданы. PR-06 не начат; записи ниже сохраняют исторические границы своих этапов.

## PR-04 — scalar Evaluator и EvaluationRequirements

По отдельному заданию владельца реализованы существующие scalar nodes, immutable field snapshot, exact compiled OperationRegistry (четыре общие операции), bounded trace и runtime budgets. [Контракт и ограничения](pr04-evaluator.md): StateIs сохраняет обязательные технические ошибки; IsComplete не равен PASS. XML 1.0.0/2.0.0 не меняются, legacy не исполняется. 172 прежние +84 runtime assertions проверены в Excel x64; Office x86 не проверен. Resolver/Writer/UI/табличное исполнение не созданы, PR-05 не начат. Записи PR-03 ниже описывают историческую границу своего этапа.

## PR-03 — типизированная структура AST / схема 2.0.0

Реализовано по отдельному заданию владельца; детали для ревью — [контракт PR-03](pr03-typed-ast.md). Flat tree, lexical bindings, доверенные exact operation signatures; структурная типизация без исполнения. Schema 1.0.0 сохраняет deferred-смысл и не обновляется автоматически. Проверены 96 legacy + 76 AST assertions в Excel x64, Office x86 не проверен. Состояния и будущая completeness не означают реализованный Evaluator или разрешение PASS. PR-04 не начат.

## ADR-008 — XML / схема / безопасная запись редакций, PR-02

**Проект решения для ревью**, реализован только ограниченный фундамент по отдельному заданию владельца. [Полный ADR-008](adr/008-schema-storage.md): MSXML6 late binding, SchemaVersion 1.0.0, generic records с закрытой Kind-схемой, точное сохранение Unicode, append-only запись нового проверенного файла; предлагаемое размещение Drafts/Published. Не означает принятия полной публикации, AST или новых бизнес-правил. [Проверка и ограничения](pr02-validation.md).

## ADR-001 — constructor-first, 19.10.2026
Решение: сначала универсальная схема, исполнитель и реальный Admin-конструктор, затем настройка NETWORK_ACCESS. Причина: отдельный проверочный движок и специализированные сетевые контроллеры старого пилота не доказали сквозную редактируемость. Статус: принято пользователем как направление; детали технического дизайна требуют утверждения.

## ADR-002 — сохраняем эталон AccessTools 1
Переписывать реализацию разрешено; менять существующее поведение без решения — запрещено. Требуется матрица проверки бизнес-семантики и реальных Excel-результатов.

## ADR-003 — сложные алгоритмы как Operations
VBA может содержать общую математическую/поисковую операцию; правила её применения, поля, источники, исключения и сообщения живут в данных.

## ADR-004 — владение Excel-результатом
Вычислитель не правит книгу. Единый Writer должен безопасно объединять аннотации, восстанавливать/сохранять пользовательское оформление и комментарии.

## ADR-005 — роли и публикация
ADMIN и Runtime разделены, FIRST_LINE и COORDINATOR получают опубликованные подходящие наборы правил; изолированные черновики, версии, откат.

## ADR-006 — архив старого пилота
Архив `archive/pilot-2026-10-18` с `6643f1c`; прежние 31 PR закрыты без merge, исходные ветки и история сохранены. В main только новая документация, никакого копирования устаревшего кода.

## ADR-007 — включительная семантика IPv4-диапазонов, 19.10.2026
**Утверждено владельцем и имеет приоритет над прежней трактовкой в ТЗ v0.13/v0.14.** Диапазон `10.0.0.1-10.0.0.10` представляет все десять адресов, включая промежуточные. Проверки Superset, разрешений/запретов, пересечений и полноты покрытия обязаны использовать весь интервал; сравнение только endpoints запрещено. Рекомендуется интервальная арифметика без перечисления адресов. `10.0.0.1,10.0.0.10` — два отдельных адреса, `10.0.0.0/24` — CIDR. Отдельные контракты: сравнение бизнес-деклараций TOP↔LOWER и сравнение математических IP-множеств, без неявной подмены семантики. Запланированная компактная запись `x.x.x.x,y` обсуждается отдельно. Регрессионные кейсы закреплены как AC-16. ТЗ v0.15: https://docs.google.com/document/d/1skCtOzRTq4_wuNNkZHSaeyWsh_sf_RjYq1OKDezmBKM/edit.

**PR-00:** подтверждён аудит 17 верхних RuleId, 26 дополнительных result paths и кандидатный каталог операций. Документационный PR #32 может быть принят с открытыми Q-01…Q-11: их не считать автоматически решёнными слиянием PR.
