# Этап 2A — ядро выполнения правил

Статус: проект решения для согласования. Реализация ещё не начата.

## Назначение и граница

Пользователь продолжает создание AccessTools-v2 по ТЗ v0.13. После готового
компилятора следующий результат — воспроизводимое выполнение скомпилированных
правил на переданных данных и объяснение полученного результата. Ядро работает
офлайн в VBA, не меняет входные книги, не запускает формулы или произвольный код.

Этап 2A реализует базовый вычислитель на синтетических контекстах. Этап 2B затем
добавляет доменные алгоритмы IP/портов, безопасные шаблоны, коллекции строк и
адаптеры источников. Успешный 2A не означает готовность всего Runtime или запуск
на реальных заявках. NoPolicyAction остаётся явной бизнес-настройкой.

## Рассмотренные подходы

1. Интерпретировать типизированный AST существующего компилятора — выбранный
   подход: сохраняет signatures, normalizer bindings и исходные позиции.
2. Генерировать VBA или Excel-формулы — добавляет второй язык выполнения,
   усложняет ограничения и обработку ошибок; отклонено.
3. Сразу реализовать весь Runtime с источниками — смешивает проверку семантики
   с чтением книг и сложными доменными алгоритмами; выделено в следующий этап.

## Модель и интерфейсы

- `ATRuntimeValue`: DataType, ValueState и отдельный payload для скаляра или
  типизированного списка. EMPTY/NULL/MISSING/INVALID различаются. Чтение payload
  не допускается при неподходящем состоянии. INVALID сохраняет диагностику
  нормализации; MISSING никогда не превращается в пустую строку.
- `ATEvalResult`: EvalState, RuntimeValue, Diagnostics и Trace. Value доступно
  только для OK. ERROR/SKIPPED/MANUAL_REVIEW не приводятся к Boolean.
- `ATEvaluationContext`: снимок именованных значений полей, идентификатор запуска,
  фиксированная дата запуска и явные настройки нормализации. Переданные значения
  копируются, чтобы изменение контекста вызывающим кодом не меняло текущий запуск.
  В 2A поддержаны только `INVARIANT` locale и `BINARY`/`ASCII_TRIM_CI` сравнения;
  другие профили дают CONFIG_UNSUPPORTED, а не используют настройки Windows.
  Дата запуска передаётся явно как Gregorian ISO date с timezone identity:
  TODAY возвращает её; преобразование timestamp в дату принадлежит адаптеру.
- `ATEvaluator.Evaluate(compiled, context)` принимает ATCompileResult, отвергает
  ошибки компиляции, отсутствующий Root и неподдерживаемые версии. Внутренний
  обход использует только статические ветви по PrimitiveId и Kind.
- `ATTraceEntry`: SourceId, Start, Length, PrimitiveId, EvalState, ValueState,
  причина и порядковый номер. Значения исходных полей по умолчанию не выводятся.
  Trace возвращается объектами; экспорт в лист/HTML не входит в 2A.

Поле, отсутствующее в контексте, даёт ERROR/RUNTIME_FIELD_MISSING. Подмена типа
поля даёт ERROR/RUNTIME_TYPE_MISMATCH. Неподдерживаемая исполняемая операция даёт
ERROR/RUNTIME_UNSUPPORTED_PRIMITIVE до чтения её операндов; успешная компиляция
сама по себе не означает наличие обработчика Runtime.

## Семантика

Нормативная основа — `docs/dsl/semantics.md`. Сначала контекст и версии, затем
вычисление слева направо. Первая вычисленная non-OK ветвь распространяется без
замены состояния и первичной диагностики. AND/FALSE и OR/TRUE пропускают правую
ветвь; COALESCE вычисляет запасное значение только при явном NULL. Пропущенная
ветвь имеет запись NOT_EVALUATED без рекурсивного обхода всех её потомков.

Именованные вызовы выполняют сохранённые ParameterBindings слева направо в
соответствующих областях видимости, defaults видят только предыдущие параметры.
Тело использует Expansion; исходный DSL повторно не разбирается. Документные
определения не захватывают значения псевдонимов строк вызывающей стороны.

Поддержанные типы 2A: TEXT, NUMBER, BOOL, DATE и однородные LIST этих типов.
NUMBER — конечный Double: инвариантный разбор без локализованного CDbl(string),
ошибки overflow и ненулевого underflow. BOOL принимает только Boolean.
DATE — дата Gregorian 0100–9999, без угадывания локализованных строк.
Нормализаторы доменных типов возвращают явный unsupported; текстовая эвристика
не заменяет IP/порт/email. RAW NULL задаётся только явным RuntimeValue.

Операции 2A: логика, арифметика, сравнения, BETWEEN, EMPTY/NOT_EMPTY,
IS NULL/IS NOT NULL, VALID/INVALID, LOWER/UPPER/TRIM/LEN, STARTS_WITH/ENDS_WITH
и текстовый CONTAINS; ABS/ROUND/MIN/MAX/SUM/AVG/COALESCE, DATE/TODAY/DATE_DIFF;
IN и ANY/NONE/COVER/CONTAINS/EXACT/OVERLAPS на поддержанных LIST.
Регистронезависимая нормализация 2A меняет только ASCII a-z; Unicode сохраняется.
Локаль не угадывается. LEN считает UTF-16 units. TRIM убирает внешние U+0020.
ROUND — ties-to-even, precision целое 0–28. BETWEEN включает границы; обратные
границы дают FALSE. Деление на ноль — ERROR/RUNTIME_DIVISION_BY_ZERO.
Остаток определяется как a - trunc(a/b)*b для Double, не через VBA Mod с
неявным округлением. Порядковые сравнения BOOL и списков не поддерживаются.

MIN/MAX/AVG на пустом списке дают AGGREGATE_EMPTY; SUM(empty)=0.
Списки сравниваются как последовательности для '=' и как множества для set ops;
дубликаты не влияют на set ops. Равенство NUMBER точное по нормализованному Double;
epsilon не вводится. Непустые/пустые/NULL/INVALID значения инспектируются по таблице
semantics.md. VALID/INVALID могут проверить доменный INVALID, но не подавляют
ошибку разрешения поля или исходный non-OK результат.

MATCHES, LIKE, SOURCE/LOOKUP, FILTER/ALLROWS/ANYROW/NOROWS, COUNT/EXISTS для строк,
DISTINCT_COUNT и доменные set signatures явно отложены до 2B. У каждого есть
отрицательный тест отсутствия обработчика. Реестр компилятора не урезается.

## Ограничения и диагностика

Отдельный `ATEvalLimits`: MaxSteps=200000, MaxDepth=64, MaxListItems=10000,
MaxTextLength=65536, MaxTraceEntries=20000. Нулевые/отрицательные лимиты и depth>128
дают LIMIT_INVALID_CONFIGURATION. Каждый посещённый узел и каждый обрабатываемый
элемент списка расходует шаг. До выделения списка проверяется размер; перед
конкатенацией/результатом строки — длина. Превышение даёт ERROR со стабильным
RUNTIME_LIMIT_* кодом. Предел trace не разрешает продолжать вычисление молча:
возвращается RUNTIME_LIMIT_TRACE, итоговая диагностика не зависит от trace capacity.
Ограничения работы, а не обещание абсолютного времени выполнения.

Native exceptions преобразуются в RUNTIME_INTERNAL_ERROR с исходной диагностикой;
не маскируют уже возвращённые ожидаемые ошибки. В DSL отсутствуют действия и I/O.
Кэш на этапе 2A не вводится: это исключает неверное переиспользование значений
между запусками и строками. Контракты determinism/cache реестра сохраняются.

Два замечания первого этапа закрываются до evaluator: nested deprecation warnings
получают SourceId определения; BIND, синтетические LIST и литералы source/lookup
получают исходный SourceId. Нужны regression tests точных source/span.

## Приёмка

1. Существующие 953 проверки компилятора остаются зелёными.
2. Полная таблица AND/OR с четырьмя EvalState, lazy COALESCE и NOT_EVALUATED;
   пропущенная ветвь с делением на ноль не создаёт ошибку.
3. Матрица шести state inspectors по всем пяти ValueState; отдельные non-OK
   входы никогда не превращаются в PASS.
4. Положительный/отрицательный/граничный тест каждого реализованного binding;
   locale independence, Unicode, malformed numbers, overflow/underflow и даты.
5. Named defaults, вложенные вызовы, повторные вызовы и отсутствие утечки scope.
6. Каждый лимит на границе и за границей; большие списки и trace не обходят бюджет.
7. Неизменность compiled AST/входного контекста, повторяемость результата и trace;
   одинаковое правило при разных явно переданных run dates не использует кэш.
8. Явный unsupported для отложенных signatures; неверная версия и тип поля fail closed.
9. Excel Compile VBAProject, полный runner, tooling gates, чистая копия и GitHub CI.
   Независимая проверка кода перед публикацией результата этапа.
