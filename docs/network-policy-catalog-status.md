# Настройки Rulebook и применение к локальным проверкам

Подключены четыре таблицы предоставленной книги правил: «Протоколы», «Проблемы»,
«Маршрутизация», «Общий текст». Это применение настроек к уже готовым десяти
локальным проверкам; вычисление правил IP, hostname, инициаторов и сервисов ещё
не входит в этот этап. Исходные алгоритмы проверок и Excel-writer не переписаны.

## Контракт

`ATNetworkPolicyCompiler.Compile(protocols, problems, routing, commonText)`
принимает успешные типизированные RAW-снимки и возвращает
`ATNetworkPolicyResult`: State, guarded Policy и Diagnostics. Policy неизменяема;
Protocols возвращает копию коллекции. CommonText принимает явный fallback.

Активность и маршруты требуют явных Да/Нет, YES/NO, TRUE/FALSE или 1/0.
Непонятные/пустые флаги блокируют настройки. Неактивные строки не дают разрешений
и не переопределяют результат. Пустой справочник протоколов остаётся пустым:
проверка допустимости явно пропускается с предупреждением.

Протоколы ограничены контрактом готового checker: 1000 уникальных значений,
1–128 символов A–Z, 0–9, `_ - . / +`, после trim/ASCII upper. Повторы удаляются.
Для остальных активных таблиц повторные канонические ключи блокируются.
Ключ сообщения строго scoped: `check|исходная severity|поле`. Ключ выбирается
до изменения важности. Wildcard/legacy-угадывание не добавлялось.

Пустые пользовательский/координаторский тексты сохраняют вычисленное сообщение;
координаторский текст при отсутствии своей настройки использует выбранный
пользовательский текст. «Штатное сообщение» не подставляется как новый шаблон:
в нём могут быть незаполненные бизнес-плейсхолдеры.
Пользовательские шаблоны поддерживают `{message}`, `{field}`, `{check}`,
`{severity}`, `{row}`. Подстановка однопроходная: вставленные данные не становятся
шаблоном. Неизвестные/непарные токены и слишком длинные сообщения дают отказ.

Лимиты: 10000 строк каждой policy-таблицы, общий compile budget 200000 шагов
с учётом длины прочитанных текстов, 65536 символов на входное значение,
32767 символов на сохранённый/развёрнутый текст. Частичной policy нет.

## Применение

`ATNetworkPolicyChecks.Run(source, loadedPolicy)` вызывает прежний local runner
с активным каталогом протоколов. `modATPolicyBindings` явно связывает существующие
коды/поля с опубликованными ключами. Несвязанные случаи сохраняют прежнее поведение.
После изменения severity PASS/FAIL пересчитываются; SKIPPED/BLOCKED сохраняются.
Системный отказ не проходит через пользовательские настройки и не может скрыться.

`ATNetworkPolicyReport` содержит:

- `AllReport` — полный результат с настроенной severity, исходными кодами и refs;
- `Decisions` — неизменяемые решения маршрутизации;
- `UserIssues`, `RequestIssues`, `SupersetIssues` — отдельные каналы;
- `UserErrorCount` — только включённые ERROR с флагом ошибки пользователя.

Общий ErrorCount и UserErrorCount намеренно различаются. Ошибка настройки остаётся
видимой BLOCKED, но не считается ошибкой ввода инициатора. Маршрут в заявку также
требует флага подсветки. Без новой настройки сохраняется включение в прежний
пользовательский отчёт; новые записи/аннотации в исходниках не включаются.

Каналы пока являются данными для следующего UI/координаторского слоя, а не
записью в исходные книги. AllReport нельзя выдавать за отфильтрованный user report.
Текущий Excel-writer по-прежнему доступен для полного ATCheckReport; интерфейс
обычного запуска и UI потребления каналов ещё предстоят.
