# Проверка структуры актуального шаблона

ТЗ v0.13 (редакция16.10) требует проверки совокупности структурных признаков до
извлечения бизнес-данных. Номер версии сам по себе недостаточен. На этом этапе
создаётся универсальный неизменяемый профиль и read-only проверка допуска.
Профиль NETWORK_ACCESS описывается по подтверждённому пользователем эталону XLSX
«Доступ к сетевой связанности.xlsx» в Drive work/Шаблоны заявок (16.10.2026).
Оригинал скачан в приватный рабочий кэш; в репозиторий входит только описание структуры.

## Решение

ATTemplateProfile содержит TemplateId, ProfileVersion, точное SheetName и optional
RequireSheetProtection. AddAnchor задаёт AnchorId, обязательный label, ограниченный
прямоугольник поиска, ожидаемые размеры merge и optional RequireLocked=True.
Новый поиск не дублируется: для каждого признака используется существующий bounded
ATExcelTableSpec с одной колонкой. Пользовательские значения не интерпретируются.
Нормализация label совпадает с текущим locator: регистр/визуальные пробелы.
Служебный якорь должен быть literal, формула с тем же результатом отвергается.
AddTableAnchor задаёт группу минимум2 заголовков: label/ожидаемая колонка/ширина merge.
Все заголовки должны быть в одной строке, с ожидаемой геометрией каждой колонки.
Это позволяет искать смещаемую нижнюю таблицу целиком: повтор одного служебного слова
в пользовательских данных не меняет fingerprint. Внутренние metadata копируются;
изменение исходного массива описания не меняет sealed профиль.

Конкретный AT_NetworkProfileV3 использует текущий title v.3.0, служебные поля и две
группы заголовков на листе «Лист1». Верхние метки фиксированы; нижняя таблица может
смещаться после строки14 до строки10000. Значения C7/C8/C12 и списки в H исключены.
Эталон сейчас не защищён и содержит unlocked labels: profile не требует защиты/Locked
искусственно и не меняет исходный файл; поддержку этих требований общий механизм сохраняет.

AddRelation(fromId,toId,minRows,maxRows,minColumns,maxColumns) задаёт допустимую
разницу координат верхнего левого якоря. Так нижняя таблица может смещаться после
добавления строк связностей, но не может оказаться над верхней таблицей/в чужих колонках.
Точный offset задаётся равными min/max. Version marker при наличии — обычный
структурный anchor. Произвольное форматирование и ввод пользователя не сравниваются.

Seal требует минимум2 признака и1 связь, известные разные концы связей, валидные
bounds. После Seal запрещено менять описание. Два AnchorId не могут разрешиться
в одну и ту же ячейку: это не два независимых признака. Ограничения:256 anchors,
1024 relations, суммарно1000000 ячеек поиска, shape<=размеров Excel.
Все пределы валидируются до поиска, отрицательные относительные offsets допустимы.

## Результат и остановка

Verify(ws) возвращает immutable ATTemplateGateResult с Allowed, Code, Detail, Message.
Совпадение: Allowed=True, TEMPLATE_MATCH. Несовпадение листа/label/merge/расположения/
защиты: Allowed=False, TEMPLATE_MISMATCH, одно сообщение
«Используйте актуальный шаблон заявки.» В Detail только AnchorId/причина, не
пользовательские значения. Неверный/незапечатанный профиль — TEMPLATE_PROFILE_INVALID;
неожиданная ошибка чтения — TEMPLATE_CHECK_ERROR; оба запрещают допуск с отдельным
понятным сообщением администратору. Нет частичного успешного допуска.

Для реального enforcement ATTemplateTableGate.Read(profile,ws,spec,lastDataRow)
сначала вызывает Verify и только после Allowed=True заново выполняет spec.Locate
и вызывает ATExcelTableReader. Старый absolute layout не принимается: допустимое
смещение нижнего заголовка не должно превращать его в бизнес-строку.
lastDataRow — актуальная граница текущего чтения; её вызывающий pipeline вычисляет
на текущем листе, не переиспользует из предыдущего запуска.
При отказе возвращает ERROR с code gate и русским Message в diagnostics, без строк.
Это вход для чтения таблицы, а не полный dispatcher приложения. Gate не вызывает
динамические macro/callback и не пишет в книгу/настройки Excel. Каждый запуск читает
текущую структуру заново; кеша по имени файла нет.

Результаты не держат Worksheet/Range. Исходник/защита/фильтры/формулы не меняются.
Остальные низкоуровневые readers сохраняются для тестов и Admin; общий runtime
pipeline должен пользоваться проверяемым входом перед бизнес-проверками.

## Приёмка

Временные листы Excel: эталон, изменение ввода/оформления без отказа, label/version/
merge/позиция/неоднозначность/формула/Locked/ProtectContents mismatch, допустимое
смещение нижней таблицы, неверный профиль и лимиты, повтор после правок/отказа,
gate раньше ошибочного data read, неизменность источника и sealed profile.
Admin-публикация/версионирование профиля, одиночные поля через общий pipeline,
rulebook, IP matcher/cache, coordinator writer и XLAM остаются следующими этапами.
