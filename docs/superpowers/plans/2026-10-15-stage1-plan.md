# AccessTools-v2 Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Создать независимый VBA compiler front-end для типизированного DSL по приложению P ТЗ v0.13.
**Architecture:** Один lexer/parser и один AST для текстового редактора и будущего UI. Registry определяет типы и signatures. Runtime Evaluator и действия не входят в этап.
**Tech Stack:** Excel VBA; Windows PowerShell для developer build/test; без сторонних Runtime-зависимостей.
**Spec:** ../specs/2026-10-15-stage1-design.md

## Global Constraints
- Runtime local-only, без Python/Node/DLL, серверов и прав администратора.
- VBA component names: допустимые identifiers, максимум 31 символ, уникальность case-insensitive.
- AccessTools-v2 не зависит от рабочей копии AccessTools 0.2.x.
- Entity IDs: [A-Z][A-Z0-9_]*; canonical uppercase.
- User DSL не выполняется через EVAL, Excel formulas, shell или динамические macro calls.
- Работать в feature-ветке, main не изменять без merge.
- Новая runtime-логика начинается только после полного DoD этапа 1.

## Review Focus
1. Ошибочный VBA-модуль не должен приводить к ложному PASS сборки: отрицательные fixtures в задаче 1.
2. Русский текст и escaping в literals не должны портиться при импорте в Excel: задача 3.
3. Alias из соседнего scope не должен разрешаться молча: задача 5.
4. Ошибка в конце длинного выражения не должна оставлять частично валидный результат: задачи 3 и 6.
5. Отсутствие Excel/доступа к VBAProject должно давать явный blocked/failure результат, не PASS: задача 1.

**Consumes:** registry IDs и diagnostics.
**Produces:** AT_Tokenize(text As String) As ATLexResult: Tokens + Diagnostics, без выполнения входа; EOF token и точные spans.

- [ ] Tests RED: @FIELD, @t.FIELD, $NAME, numbers с точкой, DATE("2026-10-15"), TRUE/FALSE, escaped quotes/backslash, Unicode literal, CRLF, invalid character, unterminated string.
- [ ] Реализовать детерминированный scanner; whitespace пропускается, raw spelling сохраняется. Reserved keywords case-insensitive; IDs с точкой разрешены только как row reference grammar.
- [ ] Проверить, что malformed suffix возвращает diagnostics и не признаётся успешным полным выражением.
- [ ] Запустить полный suite; commit: feat: tokenize rule expressions with source spans.

## Task 4: AST, parser, serializer

**Files:** src/dsl/ATAstNode.cls; src/dsl/ATParseResult.cls; src/dsl/ATParser.cls; src/dsl/ATSerializer.cls; tests/vba/modATParserTests.bas; tests/fixtures/dsl/golden.json.
**Consumes:** tokens/diagnostics задачи 3.
**Produces:** Parse(text, contextualFieldId) -> ATParseResult; Serialize(root) -> canonical text. Nodes: literal/ref/call/unary/binary/relation/list/quantifier/predicate/alias. Failed parse не возвращает пригодный к публикации root.

- [ ] Tests RED: precedence arithmetic/NOT/AND/OR; parentheses; short/full COVER equivalence с contextual field; list как один call argument; nested quantifiers с AS; field-to-field; named calls; trailing tokens.
- [ ] Реализовать recursive-descent parser, общий для всех типов, без IP/ALLROWS special parsers. Зарегистрированные multiword relation operators разбирать однозначно.
- [ ] Реализовать canonical serializer с escaping и скобками, сохраняющими semantics.
- [ ] Round-trip tests: parse -> serialize -> parse даёт структурно эквивалентный AST; repeated serialize стабилен; contextual syntax без context отклоняется.
- [ ] Запустить полный suite; commit: feat: parse and serialize typed rule AST.

## Execution and reporting
Выполнение непосредственно в текущем чате, по порядку задач; subagents не требуются. Каждый результат фиксировать отдельно: implemented / static verified / Excel verified / blocked. Готовность всего этапа не выводится из готовности первых задач. Перед кодом план передаётся пользователю на review согласно writing-plans.
