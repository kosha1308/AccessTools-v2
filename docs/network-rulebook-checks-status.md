# Общие правила в проверке заявки

Продолжение PR18. Добавлена техническая проверка NET.IP_EXCEPTIONS и новый
`ATNetworkAccessChecks.RunWithRules(source, catalog, actor, rules)`:
13 прежних исходов плюс14-й исход общих правил. Старый Run с13 исходами сохранён.
Составной результат остаётся NETWORK_ACCESS_PARTIAL_POLICY — полный выпуск не готов.

## Что выполняется

`ATNetworkRuleChecks.Run` читает RAW технические строки заявки и вызывает
проверенный Rulebook engine с одним budget на заявку. Все уникальные протоколы
разбираются буквальными разделителями (как в существующей проверке протоколов);
одинаковые токены не дублируют сообщения. Частичное покрытие портов не срабатывает.
Подтверждённое совпадение не скрывается из-за другого неизвестного протокола.

Сообщение содержит источник/назначение, порт, совпавший протокол, название правила,
сервис, группу, согласование, комментарий, инструкцию и ref строки Rulebook.
Ссылка самого issue ведёт к исходной технической строке заявки. Конфликт results
выводится отдельной ошибкой. Excel writer отображает русские названия, инструкции
и переход к ячейке в отдельной книге; исходная заявка не меняется.

Ошибки Excel и непонятный контекст явно отмечаются ручным предупреждением;
пустая таблица не даёт PASS. Лимит/системная ошибка отбрасывает частичные hits
только нового check и даёт BLOCKED. Неизменяемый флаг Incomplete сохраняется
независимо от severity: после настройки сообщений ERROR даёт FAIL, иначе
неполнота даёт SKIPPED. DefaultFalse оставляет поведение прежних исходов прежним.

## Каталог, маршрутизация и изоляция

RULEBOOK_MATCH связывается с «Правило / исключение», RULEBOOK_CONFLICT —
с «Конфликт Rulebook», ключ строится по исходной severity. По умолчанию это
координаторские результаты в Superset-канале, без ошибки ввода пользователя;
явные настройки Problems/Routing могут переопределить flags и сообщения.
Техническая остановка нового check видна, но также не считается ошибкой ввода.

Новый runner использует результат прежнего Run13 и отдельно оформляет новый check.
Затем объединяет immutable reports и decisions, не применяя шаблоны к уже
оформленным сообщениям повторно. В частности, переполнение custom template нового
сообщения сохраняет13 прежних исходов и добавляет BLOCKED общих правил.
Общий лимит1000 issues сохраняется: при нехватке места новые hits заменяются
одним сообщением остановки; если места нет совсем — явным BLOCKED reason.
