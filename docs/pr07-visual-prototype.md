# PR-07 — русскоязычный визуальный прототип

Продолжение PR #39 от `09a5648`, без слияния и PR-08. Две стандартные VBA UserForms встроены в демонстрационную `.xlsm`; дополнительных установок нет. `ui/forms.json` и `ui/demo-workbook.vba` нужны сборщику, а не конечному пользователю. Полный AST-конструктор, рабочий режим 1ЛП, Ribbon и публикация XLAM здесь не реализованы.

## Изменения интерфейса

- Кнопка листа имеет стабильное имя `AtOpenConstructor`; привязка назначается после SaveAs и проверяется при Open/Activate/AfterSave через `ThisWorkbook`. Общий `AtAdminOpen` также доступен через Alt+F8; `AtRibbonAdmin` — вход для будущего Ribbon, без создания самой ленты.
- Светлая согласованная палитра, белые карточки с отдельными заголовками, выделение правила, основная синяя кнопка, второстепенные нейтральные. Полный текст настроек сохраняется; длинные сообщения сокращаются только в обзорной карточке.
- Основное содержимое прокручивается по двум осям; заголовок, статус и нижние действия остаются вне прокрутки. Кнопки переносятся по строкам. Zoom остаётся 100, Segoe UI 10pt не уменьшается. Геометрия проверена до 480×300pt; это не подтверждение реального Windows DPI.
- Результаты компактнее: PASS зелёный, FAIL красный, незавершённый результат янтарный. Адрес, фактическое значение и замечание отделены от результата Writer. Внутренняя диагностика раскрывается отдельной кнопкой; вместо голого `OK` при FAIL даётся объяснение несовпадения.
- Сохранённый лист показывается сразу после XML load. Книгу по-прежнему требуется выбрать явно. Сохранение, выбор ячейки/Esc, предварительный тест и отдельное нанесение сохранены.

## Журналы и ограничения

Выбор папки убран. `CAtJournalStore` создаёт отдельный локальный каталог под `%LOCALAPPDATA%\AccessTools\Journals`; относительные, сетевые и reparse-пути отклоняются. Preview не создаёт журнал. Apply заново читает и вычисляет правило, не использует показанный ранее план.

Writer и его формат не заменены. Удаление возможно лишь для папки, созданной этим экземпляром store, с подтверждённым завершением всех действий, без recovery, после проверки точного manifest, размеров и содержимого файлов. Удаляются только известные файлы, затем пустая папка не рекурсивным RmDir. Неизвестные файлы/подпапки, вмешательство, активные отметки, конфликт и прерывание сохраняют данные. Подтверждённая очистка освобождает привязку к книге даже при невозможности удалить завершённый каталог; служебное пояснение остаётся в результате. Нормальные циклы не накапливают завершённые журналы. Аварийные остатки нельзя безопасно удалять по возрасту; автоматического восстановления после потери сессии нет.

Обоснование выбора и сравнение с CF/Notes v1: [анализ вариантов](pr39-annotation-options.md). Действуют все [ограничения Writer](pr06-excel-writer.md): `.xlsx` — только заливка; запрос Note отклоняет действие целиком. Заливка + legacy Note подтверждены только для `.xls`/Excel 16 build17932/Win64. Чужие Notes, CF, неподдержанное оформление и защита не обходятся. Значения и формулы не восстанавливаются из старого снимка. Writer не сохраняет книгу автоматически.

## Проверка

Excel 16.0 build17932, Office x64: **629 PASS, 0 FAIL** = 581 прежняя проверка +48 Completion. Evidence: `artifacts/run-7dc858936d6748d5975b6453021d00e8`, worker exit0, host/source-hashes и восемь result-файлов. Два прежних native Writer случая остаются UNVERIFIED; Office x86 не проверен.

Новые регрессии: уникальные каталоги и запрет присвоения владения другим store; сохранение активных, конфликтных, прерванных, изменённых и посторонних файлов/подпапок; автоматические циклы `.xlsx` и поддерживаемого `.xls`; исправленная формула; освобождение привязки при сохранённом завершённом каталоге; отсутствие файлов после обычной очистки и отказа Notes; лист до выбора книги; геометрия, читаемые шрифты, закреплённые действия и достижимость содержимого прокруткой; цвета и раскрытие диагностики.

Готовая сохранённая demo повторно открыта read-only: **14 PASS, 0 FAIL** по формам, событиям, русским подписям, идентификатору кнопки и OnAction. SHA256 `A9DF6400D10C82C8EF0FA0E3F141F529D47E8CACF77F4924D491F4A74135C026` для `AccessTools-Constructor-PR07-r4.xlsm`.

Отдельно выполнено настоящее нажатие кнопки в повторно открытой r4 через Windows Computer Use: конструктор открылся; нажатие вертикальной полосы прокрутки переместило содержимое, нижние кнопки остались на месте. До клика макрос запуска программно не вызывался. Настройки защиты Office/Windows не менялись; открывалась только собственная синтетическая книга. Старый r2 также открылся кнопкой в контролируемой копии: исходная причина отказа на машине владельца не воспроизведена. Блокированные макросы не могут показать собственный VBA-диалог; инструкции об этом видны на листе без запуска кода.

Это не полная ручная приёмка. Ранее владелец подтвердил функции и DPI125/150; для новой сборки нужны повторная проверка и отдельная фактическая проверка DPI200. Изменение размеров программно не доказывает DPI200, clipboard или удобство полного рабочего сценария.

## Короткая ручная проверка

1. Откройте r4 обычным способом, нажмите **Открыть конструктор**, затем проверьте Alt+F8 → AtAdminOpen. При блокировке сохраните текст Office; не отключайте защиту ради демонстрации.
2. При Windows125%,150%,200% проверьте читаемость, обе полосы прокрутки, достижимость всех свойств и нижних кнопок. Никакого уменьшения шрифта быть не должно.
3. Откройте отдельную синтетическую `.xlsx`: лист `Заявка`, B2=`нет`, C2=`=1+2`, пользовательская заливка и Note в соседних ячейках. Явно выберите книгу/лист, поле Text/B2, ожидаемый текст `да`, сообщение, уровень и цвет. Проверьте выбор мышью и отмену Esc.
4. Сохраните новую конфигурацию, закройте редактор, загрузите XML. Лист виден сразу, книга не выбрана. Повторно выберите книгу, измените ожидаемый текст/сообщение/цвет/координату, сохраните новую редакцию.
5. **Протестировать**: FAIL, фактическое значение, адрес и замечание; книга не меняется. Проверьте копирование только замечания, раскрытие/закрытие диагностики, отдельное поле результата записи.
6. **Нанести отметки** без выбора папки; повторить без дублей. Исправить B2 на `да` или формулу `="да"`; preview PASS не очищает, повторное нанесение снимает собственную отметку и завершённый журнал. Данные/формулы/соседнее оформление неизменны. Проверить отдельную очистку.
7. В `.xlsx` включить Note: явный отказ целиком. В поддерживаемом `.xls` повторить FAIL → заливка+Note → исправление → PASS → очистка. Изменить собственную нанесённую заливку вручную: CONFLICT сохраняет её и журнал.
8. Пустое/неверное/отсутствующее поле даёт CANNOT_EVALUATE, а не PASS. При потере сессии не пытаться автоматически усыновить старые отметки. Рабочую кнопку **Проверить заявку** для сотрудников этот PR не добавляет.

Сборка: `tools/Build-AdminDemo.ps1 -OutputPath <новый абсолютный .xlsm>`; проверка сохранённой книги: `tools/Test-AdminDemo.ps1 -Path <путь>`; полный набор: `tests/Run-Tests.ps1`. Сборка требует уже разрешённого VBA Project API; скрипты не меняют Trust Center.
