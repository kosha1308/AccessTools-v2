# Привычный интерфейс AccessTools 2.0

Пользователь 18.10.2026 утвердил развитие интерфейса первой версии без изменения
готовых проверок. Образец изучен в репозитории
[AccessTools](https://github.com/kosha1308/AccessTools): modMenu.bas,
frmResults.code.txt, modAnnotations.bas, modNetworkCoordinatorOutput.bas.
Первой версией здесь называется рабочая надстройка пользователя; README того
репозитория указывает 0.2.0-rc1, а не числовой релиз 1.0.

## Работа пользователя

Вкладка «AccessTools 2.0»: «Проверка заявки», «Шаблоны и правила», «Диагностика».
«Проверить заявку» предлагает связанности и поиск шаблона. В окне шаблонов можно
искать по русскому названию или идентификатору, проверить текущую заявку,
открыть книгу правил или заменить источники. Доступен только реализованный
NETWORK_ACCESS. Это навигация к существующим настройкам, а не завершённый
Admin-конструктор новых проверок. Другие адаптеры пока не предлагаются.

После проверки заявка активна, немодальное окно показывает замечания и подробности.
Доступны «Все проблемы», «Копировать» (все ошибки пользователя), «Перейти»,
«Повторить проверку», «Очистить отметки», «Сводка и Superset», сохранение и
диагностика. При открытом окне можно работать с листом. Буфер не меняется без клика.

Подсветка: ERROR RGB(255,199,206), WARNING RGB(255,235,156), INFO RGB(221,235,247).
Она следует прежней маршрутизации примечаний, включая явные исключения Rulebook.
При нескольких замечаниях на одной ячейке приоритет ERROR > WARNING > INFO.
Условное форматирование с собственной формулой-маркером перекрывает исходную
заливку; очистка удаляет только эти правила и собственные блоки примечаний.
Значения, формулы, чужие правила и текст примечаний сохраняются. Заявка не сохраняется
автоматически. Защищённые листы и недоступные примечания дают предупреждение.

## Рабочая копия Superset и диагностика

Проверенный контроллер по-прежнему рассчитывает те же 16 проверок и два внутренних
представления. Интерактивный слой после расчёта создаёт новую несохранённую книгу:
все листы-таблицы исходной выгрузки с исходными колонками/оформлением плюс
«Сводка координатора» и «Superset» (найденные строки). Совпадения и инструкции
копируются из уже рассчитанного представления без повторного вычисления правил.
При совпадении имён переименовывается только лист в новой копии источника.
Исходная выгрузка открывается только для чтения, с отключёнными событиями и
макросами; отпечаток проверяется относительно расчёта и после копирования/закрытия.

Внутренние книги скрываются до подготовки рабочей копии. Подробный отчёт становится
видимым только по «Диагностика», в том числе при технической ошибке запуска.
Повторный запуск закрывает лишь собственные скрытые служебные книги; открытая
пользователем диагностика и прежние рабочие результаты сохраняются.
Обычное сохранение создаёт один Superset-с-результатами.xlsx в новой подпапке.
Диагностический файл автоматически не экспортируется. При неудачной подготовке
рабочей копии сохранение блокируется, а не подменяется двумя служебными книгами.
Прямой программный AT_CommandExecute/Save сохраняет старый контракт двух книг
для существующих интеграций и тестов; он не запускает пользовательскую презентацию.

## Сборка и проверки

tools/ImportForms.ps1 создаёт дизайнерские формы из явного описания контролов и
src/ui/forms/*.formcode. Бинарные FRX в исходниках не нужны. Формы входят и в
тестовый Excel, и в XLAM. Это не создание форм во время пользовательского запуска.

Excel: compile PASS, полный набор 11353 PASS / 0 FAIL; адресный набор 83/0.
Перед исправлениями проверены RED для подсветки, рабочей копии, отсутствующих форм
и двух найденных ревью сбоев презентации (60/2 -> 83/0 с контроллером).
Первый полный запуск завершился RPC-сбоем тестового Excel на стадии контроллера;
отдельный контроллер и повторный полный запуск прошли без изменения его проверок.
Ribbon 2/0, статические сценарии 7/0. Повторное независимое чтение кода без блокеров.

Автотесты создают формы и проверяют контролы/поиск/данные, но не показывают их и
не нажимают кнопки копирования. Ручная приёмка нужна для внешнего вида, работы
немодального окна, перехода, повторной проверки из окна и вставки из буфера.
Реальные данные пользователя в комплект не включаются. Профили FIRST_LINE,
полный Admin-конструктор и официальный выпуск остаются отдельными этапами.
