заявки, Superset и сводка координатора**. Готовность одного ядра этот критерий
не выполняет. О готовности исполнитель сообщает явно, с готовым файлом/пакетом

## Что будет проверено перед выдачей

1. Заявку можно проверить обычной командой Excel без запуска разработческих скриптов.
2. Неправильные значения показываются с понятной причиной и правильной ячейкой.
3. Пустые строки и объединённое обоснование не создают фиктивных связностей.
4. Superset и координаторская сводка согласованы; ненайденные адреса остаются видны,
   множественные сервисы/ИС не теряются, hostname не выбирается произвольно.
   По обновлению ТЗ16.10.2026 обязательны также «СКУФ ГРУППА ТП (Superset)» и
   «КОМАНДА ПОДДЕРЖКИ (Superset)»: все уникальные значения из видимых связанных
   строк Superset, с новой строки. Это входит в проверку на реальной заявке перед выпуском.
5. Исходные заявка, Rulebook и Superset не меняются; результаты создаются отдельно.
6. Сравнение с действующими проверками и чистая сборка проходят; ограничения
   опубликованного выпуска перечислены явно. Отсутствующая бизнес-policy не получает
   придуманное значение по умолчанию.

Текущий код ещё не является этим рабочим выпуском. Основной ближайший результат —
подключить проверенное ядро к таблицам заявки и координаторскому потоку.
