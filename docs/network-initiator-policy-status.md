# Инициаторы, согласования и права на IP

Реализованы отдельные проверки `NET.INITIATOR_ALLOWED`,
`NET.INITIATOR_APPROVAL_RULES`, `NET.INITIATOR_IP_ACCESS`.
Они не заменяют десять завершённых локальных проверок. Новый составной runner
объединяет **13 исходов** и применяет сообщения/severity/маршрутизацию один раз.
Общий scope остаётся `NETWORK_ACCESS_PARTIAL_POLICY`: полный выпуск ещё не готов.

## Зафиксированное решение пользователя

16.10.2026 пользователь подтвердил: если разрешённый инициатор не имеет
IP-политики ни по точной почте, ни по домену, персональных IP-ограничений нет.
В опубликованном профиле NETWORK_ACCESS это явно задано константой
`AT_NETWORK_NO_IP_POLICY_ACTION = "ALLOW"` в `modATNetworkPolicyProfile`.
Общий compiler требует явный NoPolicyAction; пустое значение блокируется.
Отсутствие IP-политики не отменяет допустимость инициатора и остальные проверки.
Непонятный/неверный адрес требует ручной проверки даже при отсутствии ограничений.

## Семантика

Активные строки «Инициаторы» допускают совпавшую почту/домен. Пустой служебный
режим — обычная строка нового формата. `APPROVAL_ONLY`/«Только согласование»
не даёт допуска; другие неизвестные режимы блокируют настройки.
При отсутствии активных допускающих строк допуск явно SKIPPED. Согласования
собираются независимо со всех совпавших активных строк. Пустая/неверная почта
пропускает actor-проверки без повторных ошибок синтаксиса.

Селекторы — точная почта или точный домен с необязательным начальным `@`,
без зависимости от регистра. Списки разделяются запятой/`;`/`|`/ASCII-пробелами.
`НЕ:`/`NOT:` исключает субъект из этой строки; исключение не становится допуском.
`@user@example.test` и неверные доменные метки отклоняются. Проверка синтаксиса
почты самой заявки не ужесточалась: строгая проверка относится к policy-селекторам.

Для IP-политики совпавшие персональные строки имеют приоритет над доменными
до отбора области. Доменные строки не расширяют персональные права.
Среди выбранных строк объединяются allow и deny по области; «Любой» применяется
также к источнику и назначению. Запрошенное выражение должно полностью входить
в объединение allow и не пересекать deny. Частичное покрытие не даёт PASS.
Пустой allow существующей политики — пустое множество; весь IPv4 задаётся явно
`0.0.0.0/0`. Встроенные `НЕ:`/`NOT:` в allow добавляются к запретам.

IP, CIDR, диапазоны и маски `x`/`х` используют прежнюю интервальную математику.
Неверная policy не разбирается частично. Ядро доменов не менялось.
Пустые значения IP-таблицы имеют defaults, подтверждённые комментариями её
заголовков: Активно=Да, Область=Любой, ограничение учётной записи=Не ограничено.
Эти defaults не перенесены на другие каталоги. «Запрещено» требует пустого
значения заявки в **C10**, а не её подписи C9.

Проверяются источник и назначение верхней таблицы и фактические нижние IP.
Нижний адрес, уже покрытый успешно проверенными верхними числовыми адресами,
не требует повторного назначения стороны. Для нового нижнего адреса применяется
общая область; при наличии направленных правил неизвестная сторона явно требует
ручной проверки. Текстовая группа не скрывает запрещённые IP в других ячейках.
Нарушение имеет приоритет над неполнотой: FAIL сохраняется вместе с конкретным
значением и ref. Лимит/системная ошибка заменяет частичные успехи BLOCKED-отчётом.

Согласование по умолчанию не является пользовательской ошибкой и не попадает
в пользовательский/Superset-канал, но остаётся в канале заявки и AllReport.
Явные настройки каталога/маршрутизации могут переопределить этот fallback.
Запись подсветки/комментариев в источник ещё не подключена.

## Модули и проверка

- `ATInitiatorPolicyCompiler.Compile(initiators, ipRules, noPolicyAction)` — два RAW-снимка.
- `ATInitiatorPolicy`, `ATInitiatorSelector`, `ATInitiatorSelection` — неизменяемые правила/выбор субъекта.
- `ATNetworkInitiatorChecks.Run(source, actor)` — три actor-исхода.
- `ATNetworkAccessChecks.Run(source, catalog, actor)` — тринадцать исходов с единственным presentation pass.
- `ATNetworkPolicyChecks.Apply(report, catalog)` — выделенное применение каталога; прежний Run сохранён.

Лимиты: 10000 строк policy-таблицы, общий budget 200000 шагов с учётом текста,
65536 символов на значение, 10000 интервалов; прежние лимиты отчёта сохранены.

замечаний корректности не оставлено. Все новые проверки используют вымышленные данные.
