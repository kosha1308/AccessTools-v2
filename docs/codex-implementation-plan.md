# План работ Codex — AccessTools 2 / constructor-first

Версия: 0.15-draft, 19.10.2026.
ТЗ: https://docs.google.com/document/d/1skCtOzRTq4_wuNNkZHSaeyWsh_sf_RjYq1OKDezmBKM/edit
**Владелец передаёт задания Codex вручную.** Этот документ — roadmap, НЕ автоматическое разрешение сразу реализовать все этапы. Пока владелец не утвердил архитектуру, исполняемый код не писать.

## Рабочий цикл каждого PR
1. Codex сверяет задачу, ТЗ/ADR и зависимости, не расширяет scope самовольно.
2. Перед изменениями пишет краткий контракт входов/выходов и перечень проверок.
3. Реализует только заявленный шаг и автоматические тесты; не копирует целиком старый пилот.
4. Выполняет локальные проверки, публикует фактические команды и результаты, перечень ограничений.
5. Если нужна ручная приёмка, даёт владельцу точные действия в Excel и ожидаемые результаты. Без отметки владельца «ручное тестирование пройдено» не объявляет этап завершённым.
6. Изменения в бизнес-семантике только через согласованный ADR; несовместимое изменение блокирует PR.

## G0 — спецификация и аудит, БЕЗ кода
PR-00: реестр AccessTools 1. Источники: main и релевантные поздние ветки, checks.ini, VBA-dispatch, Rulebook, Superset, файлы примеров, ТЗ v0.13. Заполнить docs/v1-parity-matrix.md со статусами; доказать точность списка проверок, отделить роли. Тест: независимый обзор и ссылки на подтверждающий код/пример для каждой строки. Ручная приёмка: владелец подтверждает, что список полно охватывает рабочий процесс.
PR-01: каталоги сценариев и операции. В docs/operation-catalog.md классифицировать все правила как декларативные/составные/общие операции; привести образцы двух противоположных шаблонов и доказать выразимость. Тест: каждому сложному случаю соответствует выражаемая схема или явно обозначенный пробел. Гейт: утверждённая архитектура и ТЗ.

## G1 — типы и сериализуемая модель
PR-02: Template/Field/Table/Source/Rule/Action/Package схемы и валидатор структур. Обязательны идентификаторы, типы, диапазоны, референциальная целостность, цикл зависимостей и версии. Тесты: корректные/сломаные схемы, переименование координаты без изменения RuleId; два совершенно разных шаблона.
PR-03: AST и типовая система выражений, список операций и ошибок. Выбрать спецификацию и формат; без Excel UI и без бизнес-правил. Тесты: TRUE/FALSE, EMPTY/MISSING/INVALID/UNAVAILABLE, AND/OR/NOT, scope, предсказуемые ошибки, бюджет вычисления.

## G2 — чистый движок и раздельный Excel I/O
PR-04: общий интерпретатор/валидатор/компилятор конфигураций и OperationRegistry без скрытых шаблонных веток. Тесты из декларативных фикстур, в том числе разные имена/адреса и ошибочные типы.
PR-05: Field/Table Resolver для настоящего Excel, объединённые ячейки, динамические строки, безопасное чтение. Тесты фикстур + Excel smoke.
PR-06: Issue/Action Model и Writer подсветок/примечаний. Тест: повторный запуск, несколько пометок одной ячейки, восстановление пользовательских замечаний/оформления, сбой с контролируемой очисткой. Ручной тест Excel обязателен. До его подтверждения архитектуру Writer не замораживать.

## G3 — первый вертикальный конструктор (главная продуктовая точка)
PR-07: Admin UI: создать новый TemplateId, выбрать образец, зарегистрировать FieldId, выбрать координату на листе. Тесты: сохранение/загрузка, распознавание неизвестного и подходящего файла.
PR-08: Admin UI: создать/редактировать/клонировать/отключать одну простую RuleDefinition и настроить цвет/примечание/текст/целевой адрес. Сквозная ручная проверка на реальном Excel обязательна. **Критерий: всё выполнено через UI, без VBA/ручной правки внутренних файлов.**
PR-09: управление черновиками, Test/Explain, предварительный просмотр действий, публикация/откат. Тесты: ошибка компиляции блокирует релиз, draft не виден runtime, rollback восстанавливает значение. Гейт: первый независимый шаблон действительно создан и опубликован через UI.

## G4 — расширение редактора и источники
PR-10: дерево AND/OR/NOT; ANY/ALL/NONE/COUNT для таблиц; ссылки на поля; валидация scopes/циклов. Тесты: вложенные условия и пустые/неполные строки; UI-редактирование сложного дерева.
PR-11: каталог SourceDefinition/Binding, UI выбора файлов/листов/колонок, lazy index/cache, ошибки схемы/отсутствия. Тесты: два шаблона используют один источник; повтор без лишнего чтения, строгая invalidation.
PR-12: каталог зарегистрированных операций и редактор параметров, шаблонные параметры/приоритеты/исключения. Тесты: одна операция вызывается из разных шаблонов и UI; конфликтные правила.
PR-13: второй отличный от первого рабочий шаблон через Admin (до NETWORK_ACCESS), без нового шаблонного кода. Ручная приемка: оба экземпляра корректно распознаются и используются без вмешательства разработчика. Гейт: универсальность доказана.

## G5 — сеть и эталонный NETWORK_ACCESS
PR-14: общие IP/CIDR/hostname/порт primitives как чистые OperationId. Выборочно переиспользовать старую IP-математику только после контрактного ревью. **Утверждённый ADR-007:** дефисный IPv4-диапазон интерпретируется полностью и включительно, а не как пара конечных адресов; использовать интервальную арифметику. Тесты: запрещённый IP внутри диапазона, неполное покрытие, только крайние IP в источнике, обратный/невалидный диапазон, большие диапазоны без полного разворачивания, отдельная семантика TOP↔LOWER, порты, CIDR, hostname, некорректные значения. PR-00 выявил, что прямой портовый lookup в Superset пока не подтверждён: не заявлять это наследованной функцией без согласованной схемы.
PR-15: Superset, Rulebook и политики как общие SourceBindings и операции, не контроллер шаблона; индексы lazy. Тест: найдено/не найдено, дубликаты, согласования, отказ/разрешение, отсутствие файла, схема.
PR-16: через Admin зарегистрировать Excel-шаблон NETWORK_ACCESS и создать/изменить каждую его RuleDefinition из реестра. Не импортировать закрытый VBA-маршрут. Контроль: каждый ID открывается и изменяется в конструкторе.
PR-17: результатные книги, coordinator summary, Superset с найденными/ненайденными и обогащением; Writer и RoleRouting общий. Тест: сохранность оригинала, имена/поля/семантика как у v1. Гейт: 100% матрицы паритета с эталонными Excel-кейсами, отклонения объяснены и утверждены.

## G6 — роли, установка и выпуск
PR-18: пакеты FIRST_LINE и COORDINATOR на общем Runtime, разделение функций/источников и публикация. Smoke-тест: первая линия не загружает ненужный Superset, координатор получает нужное.
PR-19: диагностика, кеширование, восстановление Excel state, скорость старта и больших книг, наблюдаемость ошибок.
PR-20: воспроизводимая сборка XLAM, ZIP, инструкция развёртывания, обновление и rollback; полная регрессия, manual Excel acceptance и финальный release checklist.
